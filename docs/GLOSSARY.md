# Glossary

faff coins a lot of vocabulary, and every coined noun is load-bearing because it names an artifact — a file, a CLI command, a hook, a contract. Each row below is a lookup: one sentence, one artifact. It is not documentation — the normative prose stays where it lives (the gateway, an ADR, `faff contract <name> --describe`); if you need the full rule, follow the artifact column there.

## Terms

| Term | Meaning | Artifact it names |
|---|---|---|
| adapter | The spelling faff prose standardises on for a slot's swappable occupant (the legacy `adaptor` spelling is deprecated in prose); the CLI keeps its existing `validate-adapters` name. | `faff validate-adapters` (`plugin/skills/faff/bin/lib/validate-adapters.js`) — see **Naming decisions** |
| admissibility | The lights-out check that a spec's Definition of Done is machine-checkable enough for an unattended build to grade its own done, run as a backstop before a direct L4 `/faff-graft`. | `faff admissible` (`plugin/skills/faff/bin/lib/admissibility.js`) |
| appetite | The dial (`low`/`medium`/`high`/`full`) that sets how much rope the autonomous pipeline gets before checking back — it never loosens the hard floor (no autonomous cancel/delete, no autonomous ADR supersede past the admit gate). | `appetite` key in `.faffrc.yaml`; gateway → **Appetite for destruction** |
| born-verifiable | A DoD criterion class (`scenario`/`assertion`) the evaluator may machine-judge itself, as opposed to `prose`, which is always forced to `needs-human`. | `faff dod classify` (`plugin/skills/faff/bin/lib/admissibility.js`) |
| cage | The container an L4 lane runs inside — faff implements no sandbox of its own; any containerised Claude Code satisfies the isolation requirement. | `faff container-check` (`plugin/skills/faff/bin/lib/container-check.js`); ADR 0041 |
| channel | The reserved term for a step in the sentry corrective ladder — e.g. **Channel A**, stop-and-redispatch with a machine-authored, subtractive-only corrective input. Reserved by the naming decision below (execution folds into FAFF-74). | ADR 0062 |
| concurrency | The mechanism slot that executes the build-pass for `/faff-beep-boop` — sequential by default, or a capped, worktree-isolated parallel executor. | `slots.concurrency` in `.faffrc.yaml`; default `faffter-noon-concurrency-sequential` |
| contract | A fixed, versioned data shape a producer slot emits as a `faff-contract:<name>` block and a deterministic CLI validates — e.g. `review-verdict`, `quality-gates`, `delivery-outcome`. Never restate a contract's enum values outside its own describe surface. | `faff contract <name> --describe` (`plugin/skills/faff/bin/lib/contract-engine.js`, `contract-defs.js`) |
| dial | The generic term for a graded, human-set configuration knob (appetite is the best-known one) — as opposed to a binary flag. | `appetite` key in `.faffrc.yaml`; gateway → **Appetite for destruction** |
| DoD | Definition of Done — a spec's `## Scenarios` + numbered `### N. DONE` criteria, classified by born-verifiability before an evaluator or a build gate acts on them. | `faff dod classify` / `faff dod split` (`plugin/skills/faff/bin/lib/admissibility.js`) |
| envelope | The fixed shape of a contract block's payload (field names, types, nesting) — distinct from its enum semantics, which live at `faff contract <name> --describe`. | `plugin/skills/faff/bin/lib/contract-defs.js` |
| evaluator | The code-blind holdout producer slot: given a spec and a running environment but never the codebase, it exercises born-verifiable criteria and emits a `holdout-verdict` block. | `slots.evaluator` in `.faffrc.yaml`; default `faffter-noon-evaluate` |
| fence | A PreToolUse hook that mechanically denies a specific dangerous call shape rather than relying on prose — e.g. `merge-fence` denies a raw `gh pr merge`, `background-fence` denies a backgrounded gate command. | `plugin/skills/faff/bin/lib/merge-fence.js`, `background-fence.js` |
| floor | Never appears bare — always compounded (merge floor, no-execute floor, appetite hard floor, structural/topology floor). Each compound names its own non-delegable minimum a producer or slot may extend but never weaken. Execution of this compounding rule across existing prose folds into FAFF-74. | see **Naming decisions**; e.g. `faff merge-gate` (`plugin/skills/faff/bin/lib/merge-gate.js`) for the merge floor |
| gate | A point in the pipeline where a skill decides whether/how to act on an issue, backed by a deterministic assertion rather than agent narration — e.g. the merge-confidence gate, the engineering gate ladder. | `faff gates run` (`plugin/skills/faff/bin/lib/gates.js`); `faff merge-gate` (`merge-gate.js`) |
| graft | The verb/skill that drives a single issue's build end-to-end — worktree, spec commit, build, gate ladder, review, PR, merge. | `/faff-graft` (`plugin/skills/faff-graft/SKILL.md`) |
| heartbeat | A per-run, per-issue liveness tick written during a long, quiet build/review sub-step so the sentry poller doesn't read an active run as abandoned. | `faff heartbeat` (`plugin/skills/faff/bin/lib/heartbeat.js`) |
| holdout | The code-blind evaluation of a merged-or-about-to-merge feature against its spec, by a lane that never saw the implementation — the L4 per-issue merge condition and the per-run L4 phase. | `faff holdout verdict` (`plugin/skills/faff/bin/lib/admissibility.js`); `faff-contract:holdout-verdict` |
| implementor | The innermost agent lane: full codebase read/write, sees the spec, builds and iterates — no tracker access, no project-level sequencing. | gateway → **Agent Lanes** |
| lane | One of the three structurally isolated executor contexts (orchestrator / implementor / evaluator) with controlled visibility, so the build agent can't mark its own homework. | gateway → **Agent Lanes** |
| leash | The deliberate hold that keeps a DoD-gated container (e.g. a PRDR-tracked project) open until a run actually supplies holdout verdicts — an absence of verdicts is a by-design not-passed, not a defect. | `faff holdout verdicts --association` (`plugin/skills/faff/bin/lib/admissibility.js`) |
| ledger | The per-run JSON record of admitted issues and their terminal outcomes, audited at run-end so a run can never call itself "done" while leaving admitted work dangling. | `.faff/runs/<run-id>/run-ledger.json`; `faff runcheck` (`plugin/skills/faff/bin/lib/runcheck.js`) |
| mint | The verb for producing a fresh, strict-defaults L4 run-ledger + trust banner once the lights-out preflight passes. | `faff lights-out` (`plugin/skills/faff/bin/lib/lights-out.js`) |
| orchestrator | The outermost agent lane: tracker + human dialogue + pipeline sequencing — decides what runs when, never touches implementation detail. | gateway → **Agent Lanes** |
| park | The verb/state for an issue the autonomous pipeline can't safely resolve on its own — a WIP commit, a draft PR, a tracker comment naming the cause, and the `faff-parked` label. | gateway → **Park protocol**; `faff label add <issue> faff-parked` |
| prep | The verb/skill that turns a vague ticket into an attached, reviewed spec before any build starts. | `/faff-prep` (`plugin/skills/faff-prep/SKILL.md`) |
| PRDR | Product-Requirements Decision Record — the supersedable, product-axis decision log between the immutable PRD and a per-slice spec, with its own admission/coverage/yagni gates. | `faff prdr` (`plugin/skills/faff/bin/lib/prdr.js`); `docs/prdr/` |
| producer | A slot category that authors an artifact (spec, review verdict, delivery outcome, ADR body, …) and emits it as a `faff-contract:<name>` block for a deterministic CLI to validate — as opposed to an adaptor, which only reshapes or renders. | gateway → **Core contracts and adaptor slots** |
| region | The faff-owned span of a tracker comment body — the text strictly between a marker-pair like `<!-- faff-review-findings:<ID> -->` … `<!-- /faff-review-findings:<ID> -->` — that a rewrite may replace while everything outside it (a human's own edits) stays untouched. | gateway → **Review-findings comment identity** |
| rung | Reserved for the isolation/trust ladder — the L1–L4 level table and the multi-cage isolation ladder (ADR 0041). Never used for external-verification levels (those are tiers) or sentry corrective steps (those are channels). Execution of this reservation across existing prose folds into FAFF-74. | gateway → the L1–L4 levels table; ADR 0041; see **Naming decisions** |
| seam | A documented hand-off point between two components (e.g. a pure function signature) that is built once and later callers plug into or replace without touching the surrounding plumbing. | gateway → e.g. **Agent Lanes → Implementor** (the bare-executor seam) |
| sentry | The corrective/watchdog layer that supervises a running unattended loop and can pause, abort, or (Channel A) issue a subtractive corrective redispatch. | `faff sentry check` / `faff sentry-poller` (`plugin/skills/faff/bin/lib/sentry.js`, `sentry-poller.js`) |
| slot | A named, swappable delegation point in the pipeline (e.g. `review`, `ship`, `methodology`) with a faff-owned default — the mechanism behind "configurable, not opinionated." | `.faffrc.yaml` `slots:` key; gateway → **Slots (optional delegation)** |
| spec | The durable, reviewable artefact a build is gated on — produced by the `spec` slot, attached to the tracker issue, and committed to the feature branch on graft. Never a substitute description, however well-written. | `/faff-prep`; gateway → **Spec discovery** |
| tidy | The verb/skill that grooms the backlog in both directions — finds problems and promotes ready issues to Todo. | `/faff-tidy` (`plugin/skills/faff-tidy/SKILL.md`) |
| tier | Reserved for the external-verification P-levels (P1–P5) — the throwaway scaffolded SUTs faff's own lab runs itself against. Never used for the L1–L4 trust ladder (that's rungs) or sentry corrective steps (that's channels). Execution of this reservation across existing prose folds into FAFF-74. | `docs/external-verification/README.md`; see **Naming decisions** |
| verdict | The fixed, closed-vocabulary outcome a producer's contract block carries — never a free-text judgement. Its exact value set is per-contract, not restated here. | `faff contract <name> --describe` |
| wave | One re-entry pass of `/faff-beep-boop`'s queue assembly, where eligibility, status, and human edits are re-read fresh before the next batch of issues is picked. | `/faff-beep-boop` (`plugin/skills/faff-beep-boop/SKILL.md`) |
| worktree | The isolated git checkout `/faff-graft` provisions per issue, under the resolved worktree root, so a build never touches the main checkout. | `plugin/skills/faff-graft/setup-worktree.sh`; `faff worktree-root` (`plugin/skills/faff/bin/lib/lights-out.js`) |

## Naming decisions

Three decisions are recorded here as the target for existing prose; execution — the actual sweep and rename across the repo — folds into **FAFF-74** whenever that vocabulary migration runs. New prose should already follow these.

- **`rung` is reserved for the isolation/trust ladder.** The L1–L4 level ladder and the multi-cage isolation ladder (ADR 0041) keep `rung`. External-verification P-levels (P1–P5) become **tiers**. Sentry corrective ladder steps become **channels** (the Channel A/B language ADR 0062 already uses). Execution folds into FAFF-74.
- **`floor` never appears bare.** It is always compounded — merge floor, no-execute floor, structural/topology floor, appetite hard floor — because a bare "floor" cannot be bound to a single artifact. Execution folds into FAFF-74.
- **Prose standardises on `adapter`.** The CLI already spells `validate-adapters`, so renaming the CLI is the expensive direction; prose converges on the `adapter` spelling (the majority spelling already), with the legacy `adaptor` spelling treated as deprecated-in-prose. Execution folds into FAFF-74.
