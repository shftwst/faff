# ADR 0063 — Fleet authority & state model — member-scoped supervision is subtractive and boundary-only

- **Status:** Proposed
- **Date:** 2026-07-12
- **Issue:** FAFF-327

## Context

ADR-0039 (Sentry-2 corrective-authority) settled **per-run** Sentry supervision for v1 and explicitly deferred **fleet** supervision — one supervisor over the `faffter-dark-concurrency-parallel` build fleet — as its costed follow-up 3, gated behind "the single-value heartbeat-file decoupling." The reason fleet supervision was inadmissible at v1: Sentry's liveness evidence aggregated at run scope (`evalWallClock` read one run-level heartbeat), so under N concurrent build subagents sharing one run, a single stalled member was invisible for as long as any peer kept ticking — and the only lever the intervention ladder offered against it was run-scoped `abort` (killing every healthy build to stop one dead one). A fleet-level corrective artifact would also have added a new shared-mutable-state write surface, violating the admissibility criterion this ADR restates verbatim below.

The precondition has since landed: FAFF-355 shipped the dedicated single-value run heartbeat file (`.faff/runs/<run-id>/heartbeat`, tmp+rename, single orchestrator-facing writer per tick) and named its own extension point for exactly this consumer — "suffix the filename (`heartbeat.<issue>`), take the max at the read seam." FAFF-352 separately wired `faff sentry check` into beep-boop's between-units checkpoints (the `sentry-checkpoint` event + the canonical checkpoint procedure), giving the parallel executor's await-all gate a place to actually consult Sentry while N members are in flight. With both preconditions merged, this ADR settles the fleet authority and state model FAFF-327 builds.

## Decision

**Fleet supervision is the same Sentry, member-resolved — never a second watcher lane.** `faff sentry check` gains one new pure predicate (`evalMemberStall`) that reads each in-flight member's own single-writer `heartbeat.<issue>` file (written only by `faff heartbeat --unit <issue>`, that member's own tick) alongside the existing run-level surface, and can therefore attribute a stall to **one** member without the run itself being runaway. This is additive evidence over the same evaluator, not a new supervisory component — ADR-0039's "who-watches-the-watcher: no new lane" stance holds unchanged at fleet scope.

**Zero new shared-mutable write surfaces — the admissibility criterion, verbatim.** Every evidence surface this decision adds is single-writer: one `heartbeat.<issue>` file per member, written only by that member's own tick (mirroring the run file's own single-orchestrator-tick model, FAFF-355). `faff sentry check` stays read-only, report-only. The run ledger keeps its post-FAFF-355 single writer (the orchestrator). No fleet-level status file, member-verdict cache, or ledger annotation is introduced. An implementation that adds any fleet-level mutable artifact with more than one writer is rejected by this ADR, not merely by review.

**Member-scoped authority is subtractive-only and caps at `pause` — it never escalates to run-wide `abort` by itself.** A member-scoped `wall-clock-runaway` verdict (`scope:"member"`, `member:<issue>`) contributes at most `pause` to the intervention ladder-max: park the stalled member at its boundary, let the fleet run on. This is ADR-0039's write-abstention template applied at member scope — the machine-detected signal can only narrow (withdraw one member), never widen. The existing run-scoped `abort` route is untouched: if *every* member goes silent, nothing ticks the run-level heartbeat file either, so the pre-existing run-scoped `wall-clock-runaway` → `abort` predicate still trips exactly as it did before this ADR — the kill-switch story is preserved **by construction**, not by new fork-on-level logic. `fix-review-thrash` / `repeated-identical-failure` verdicts additionally gain the same `scope`/`member` fields when their evidence already names a single issue — purely additive attribution for auditability; their own mapped intervention (`SIGNAL_TRIP_INTERVENTION`, unchanged) is never altered by carrying that annotation, so a fleet member that thrashes or repeat-fails still drives the same run-scoped response it always did outside a fleet.

**Member interventions act at member boundaries only — never by live interference with a running subagent.** This is ADR-0039's constraint 2 ("orchestrator-lane authoring, dispatch-boundary consumption") applied at member scope: the orchestrator acts on a member only once its agent is dead (liveness genuinely stale on both `heartbeat.<issue>` and its `build-start` baseline) or has already returned (its slot is idle). A live-but-slow member is never interrupted mid-flight; it is left to keep polling until it either recovers or is caught at its own boundary.

**Member-park is orchestrator housekeeping at every level; run-scoped `abort` stays mint-scoped.** Unlike `abort` (an authority-laddered act — only an L4/lights-out run acts on it; a non-L4 run only logs + surfaces), parking a liveness-dead member runs at **every** level. This is a deliberate departure from ADR-0039's "acts are mint-gated" default, justified because member-park is *recording reality and preserving WIP* — the same thing an orchestrator already does for a silently-dead subagent outside any Sentry involvement — not an exercise of corrective authority over live work. It is fully reversible: re-running `/faff-graft` on the parked issue resumes from its committed branch + draft PR. The member-park procedure (confirm boundary → commit WIP → post the park comment citing the verdict evidence → apply the park label → record the ledger outcome `parked` → free the slot) lives once in the parallel executor's await-all gate and is never duplicated.

**Fleet evaluation is auto-detected from existing evidence — no new flag, no behavioural opt-in.** In-flight members derive from `build-start` events minus terminal ledger outcomes — the same events+ledger surface `sentry check` already reads. A run with no in-flight members (sequential, legacy, or interactive graft) computes an empty set and its payload is byte-equivalent to the pre-FAFF-327 surface by construction, not by a conditional branch a future edit could drift.

**Correctives stay out of scope.** This ADR governs *detection + subtractive park*, not authoring a corrective input at a member's re-dispatch boundary — that remains Channel A / Sentry-2 territory (ADR-0039, FAFF-325/326), gated behind the corrective-artifact integrity mechanism. The member-park procedure names the extension point (where a corrective input would attach once admissible) without building it.

## Consequences

- **ADR-0039's costed follow-up 3 is discharged.** Fleet supervision now exists; per-run supervision (ADR-0034) and per-run corrective authority (ADR-0039/FAFF-326) are unchanged — this ADR extends the authority model to fleet scope without revising either.
- **The intervention ladder's meaning is now scope-qualified.** `pause` from a member-scoped trip means "park one member, the fleet continues"; `abort` remains exclusively run-scoped and mint-gated. A future reader of a `sentry-checkpoint` event must check `scope`/`member` before assuming a verdict describes the whole run.
- **The parallel executor's await-all gate is the sole fleet consult site.** It runs the canonical between-units checkpoint (FAFF-352, referenced not restated) every poll iteration — the only component awake while N members are in flight, and therefore the only place a member stall can be caught before the member's own subagent returns.
- **`stall_window_secs` is reused, not duplicated.** Members tick through the same graft call sites the run-level window was calibrated against, so the false-positive tradeoff is the one already accepted; a member-scoped false positive is also cheap to be wrong about (park-with-WIP, resumable), unlike the run-scoped abort it replaces for this case. A dedicated `sentry.member_stall_window_secs` remains a named, uncommitted extension point if calibration evidence ever justifies a separate window.
- **A future fleet-scoped corrective (Channel A at member granularity) has a named attachment point** — the member-park procedure — but is not admissible until the FAFF-325 corrective-integrity precondition is proven, exactly as ADR-0039 already gates issue-scoped Channel A.
- **If the single-writer-per-member invariant is ever broken** (e.g. a future change lets more than one process tick the same member's heartbeat file, or a corrective mechanism gains a second writer into fleet-scoped state), this ADR's admissibility criterion is violated and the fleet supervision model must be re-examined — the same revisit discipline ADR-0034/0039 already apply to their own un-subvertability and integrity claims.
