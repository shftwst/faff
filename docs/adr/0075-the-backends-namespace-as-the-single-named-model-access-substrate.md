# ADR 0075 — The backends: namespace as the single named model-access substrate

- **Status:** Proposed
- **Provenance:** human
- **Date:** 2026-07-16
- **Issue:** FAFF-523

## Context

faff had exactly one place able to name a foreign model/provider/host/key: the adversarial review's bespoke `faffter_dark.adversarial.{provider, model, host, api_key_env, fallbacks}` block. Every other producer runs as a Claude subagent selected only by a `models.X` Agent-token tier (`inherit|sonnet|opus|haiku|fable`), a vocabulary that cannot express a provider, host, or key. Three drivers push against this: heterogeneity (an adversarial second opinion or a code-blind holdout judge wants a genuinely different model family), cost (a cheaper or local model absorbing high-volume build/eval traffic), and privacy/data-residency (a lane whose inputs must never leave the machine). The first two are satisfied by picking a good backend; the third can be *violated* — pointing a secrets-touching lane at an external API is a data leak, not a suboptimal choice — so it needs an enforcement surface, not a passive default. faff already had two endpoint dialects sharing the same core record (`provider/model/host/api_key_env/reasoning_off/timeout`): the top-level `engines:` map (`faff engine call`, ADR-0054) and the adversarial inline block. A third dialect was rejected as unnecessary fragmentation.

## Decision

Introduce a top-level `backends:` map (name → `Backend` record) as the single named model-access substrate, generalizing `engines:` rather than sitting beside it. Each `Backend` carries `provider`, `model`, `host`, and two first-class dimensions: `auth: subscription-seat | api-key | none` (with `subscription-seat` binding to the *ambient interactive session* — no `seat_ref` handle field; that was dropped in the 2026-07-16 operator resolution to defer FAFF-478's seat-mechanics spike without pre-committing a shape) and `egress: local | external` (derivable from provider/host, explicit value always wins). A consumer references backends via an ordered `refs:` list — index 0 first-served, no named "primary" (the FAFF-261 flip) — and may declare `requires: local`; any resolve to an `egress: external` backend inside that chain fails closed at run start with a residency-violation, never a mid-run leak. `engines:` entries fold into `backends:` at load with a name collision treated as a hard error, and the `engine:<name>` lane prefix is retained indefinitely — no rename, no sunset date, zero breakage to shipped configs. `provider: anthropic` is permitted at the namespace level (it must be nameable — that is the whole subscription-vs-API point) but `faff engine call` still refuses it as a consumer-side rule, since that transport has no anthropic support.

## Consequences

Every future model-access consumer — cost-aware routing (FAFF-452/479/480), subscription-seat auth mechanics (FAFF-478/481), and the eventual capability/role/invocation refactor (FAFF-69/70/72) — resolves *through* this shape instead of re-inventing endpoint config. The FAFF-478 seat-handle spike is deferred rather than blocked: `subscription-seat` needs no field here, so that spike can land later without touching this schema. The residency fail-closed posture composes with the lane-isolation/secret-ownership work (FAFF-32/107, ADR-0073) rather than duplicating it. Existing `engines:` configs and the adversarial block's legacy inline-record shape both keep resolving unchanged — migrating a consumer onto named `refs:` is opt-in, not forced. The trade-off accepted: named `backends:` entries do not inherit optional fields from one another (unlike the legacy `fallbacks` inheritance), so any future migration of an inheriting config must restate previously-inherited optionals explicitly to stay byte-equivalent — a one-time migration cost, not an ongoing one.
