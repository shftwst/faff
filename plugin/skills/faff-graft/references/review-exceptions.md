# Review dialogue, judge and holds

Step 9 supplies the remote-backed diff and the common terminal claim and label cleanup.

**Build-review dialogue (autonomous Phase-2 criticals only).** Enter on `escalated_criticals[]` with `graft.build_review_judge` enabled (default). Use the private `$run_dir/<ISSUE>/build-review` history. Start at round 1, or use the saved `next_round` on resume. Before invoking the independent reviewer, keep that ordinal for its return.

1. Pipe the settled review-verdict JSON, including the occupant's unedited `escalated_criticals[]`, to `faff build-review-round record --run-dir "$run_dir" --issue <ISSUE> --round <n> --diff-hash "$cur_hash"`. Retry the same ordinal and return on exit 2 once. Log the carry IDs and refusals. Any remaining error → pre-PR needs-human park.
2. Follow `action`: `pass` → terminal evidence and 9b, `fix` → ordinary fix loop, `judge` → would-be-park judge, `park` → needs-human, `unavailable` → outage path. For `reply`, the author chooses a fix (apply, test and commit it) or a rebuttal per standing critical. Pipe the array to `faff build-review-round reply --run-dir "$run_dir" --issue <ISSUE> --round <n>`: each entry has `finding_ref` from `curr_critical_ids` and `kind: fix` plus `fix_commit`, or `kind: rebuttal` plus `rebuttal_text`. Only the reviewer can withdraw a finding. A pending rebuttal confirmation returns `judge` even when the reviewer withdraws the last critical after a later fix. Send the recorded case.
3. Apply the same exit handling to `reply`. Re-review with the returned `next_round`, recaptured diff, prior findings, and only the persisted `author_replies` from `path` as scrubbed untrusted context. With `reply_recorded`, reuse those replies. A spent turn budget → built-but-not-admitted hold with the returned counters.

**The would-be-park judge.** `faff build-judge-evidence --assemble --dir <build-review-dir> --issue <issue> --diff <diff-file>` (the file the **Remote-backed review diff** block captured for the latest review round) assembles one blinded, scrubbed `BuildJudgeCaseFile` per finding requiring adjudication (Argument A = the independent reviewer's finding, Argument B = the author's last rebuttal or a labelled null-defence, order coin-swapped), writes `<build-review-dir>/judge/case-<case_id>.json` + `ledger.json` (mode 0600), then dispatches the two-phase judge per case (Phase 1 blind reconstruction, Phase 2 rule — one `faff-contract:build-judge-verdict` block per case; the outcome vocabulary is canonical at `faff contract build-judge-verdict --describe`), bounded-retrying a transport outage up to `graft.build_judge_retry_limit`. `faff build-judge-evidence --admit --dir <build-review-dir> --level <level> --run-dir <run_dir>` rolls the ledger up: admit only when every blocking finding overturns and no non-overturned finding remains (a single overturn among several standing criticals never admits). On admit → `faff evidence write review-verdict --judge-admitted --run-dir "$run_dir" --issue <ISSUE>` (it checks the judge's own `admit-result.json`), then Step 9b (PR). On not-admit → the same `needs-human` park as today (`review-verdict.json` written via `--park needs-human`, `faff-parked` applied) — the judge never asserts admission, and park is the default on any unresolved state.

**Chunked judge calls.** Run each `--assemble` as its own foreground Bash call with `timeout: 600000`; it stops inside `graft.build_judge_call_budget_secs` (default 540) with its ledger persisted and exits `3` (incomplete). While it exits `3` and its printed `attempts_remaining` is lower than the previous call's (the first exit `3` always re-invokes), tick `faff heartbeat "$run_dir" --unit <issue>` and re-invoke it with the same arguments; on any other exit, or when `attempts_remaining` did not fall, stop looping and run `--admit`, whose fail-closed exit on an unresolved case parks.

**The `unavailable` disposition.** Provider outage is availability. Run **Prepare a build review hold** below with cause `review-outage`. Interactive review takes its `park` route. A standing or judge-upheld critical uses `needs-human`.

**The `built-but-not-admitted` hold.** When an autonomous review or judge runs out of turn budget mid-dialogue, run **Prepare a build review hold** with cause `build-review-dialogue`.

**Prepare a build review hold.** Run `faff resume-store prepare-hold --run-dir "$run_dir" --issue <ISSUE> --store-root "$repo/.faff/resume" --cause <cause> --mode <interactive|autonomous>`. Add `--resumed` on Step 3's store-resumed path and both `--fix-rounds-used <n> --rebuttal-rounds-used <n>` if the build has dialogue rounds. If the response was lost, repeat the identical call for this run and issue to recover the receipt before any tracker effects. Exit 4: wait briefly and repeat the same call once. A confirmed other non-zero exit or a second exit 4 takes the corresponding `needs-human` park.

- **`hold`**: no PR or terminal review verdict. Apply `faff label transition <ISSUE> <role> --present-label <each current state label>`, using the returned role. It clears the claim breadcrumb. Release the Step-5 claim via the lease-matched `faff build-claim release --issue <ISSUE> --sha <sha>` best-effort, release `In Progress → Todo` as the claim-holder, and post `notice`. Return `token`; the ledger uses `parked` plus the appropriate pending annotation.
- **`park`**: write the review verdict via `faff evidence write review-verdict --park <signal> --run-dir "$run_dir" --issue <ISSUE>`. Park `needs-human` with `reason` and follow terminal cleanup when `clear_store` is true. Return `needs-human`.
- **`stale`**: log the stale hold and return `errored`. Leave the current store, tracker state and claim untouched.
