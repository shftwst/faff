# Faff gateway reference — L4 concurrency & evaluator

> Part of the faff gateway. Read on demand by the skills whose lane consumes it (see each skill's load-line). Cross-references of the form `gateway → **Section**` resolve against the kernel and all references pooled.

### Evaluator (external lane)

**Visibility:** Documentation, specification, stood-up environment (runtime access). **No codebase access.**
**Not concerned with:** How the code works. Only whether the delivered artefact satisfies the spec from a business-value perspective.

Quality control from the outside:
- Can the feature be exercised in the running environment?
- Does the behaviour match what the spec promised?
- Are acceptance criteria met from a user's perspective (not a code perspective)?
- Does the delivered value match the problem statement in WHY?

This lane is intentionally blind to implementation — it evaluates outcomes, not code. A passing evaluator signal means the feature works as specified regardless of how it's built.

### Lane isolation

The lanes have **controlled visibility by design**, not by accident:

| Lane | Codebase | Tracker | Spec | Environment | Human dialogue |
|---|---|---|---|---|---|
| Orchestrator | Read (context) | Full | Read | No | Yes |
| Implementor | Full read/write | No | Read | Local dev | No (via orchestrator) |
| Evaluator | **No** | No | Read | Runtime access | No (via orchestrator) |

| Secret class | Orchestrator | Implementor | Evaluator |
|---|---|---|---|
| Agent-engine credentials | Yes | Yes (incl. adversarial-review key, scoped to its helper process) | Yes (its runtime helper is itself an LLM process) |
| Forge credential | Yes | Yes | No |
| Tracker credential | Yes | No (host-session tool grant, no lane-held key) | No |
| Project runtime secrets | No | Yes (local dev) | No (gets synthetic credentials instead) |
| Synthetic SUT credentials | Transit only, never persisted | No | Yes (its runtime input) |
| Engine-context vars | Yes | Yes (local dev) | No (endpoint URLs only, never the engine) |
Secrets get the same treatment: the evaluator's complete visible set is an engine credential, the env-handle's contents, and the spec text — nothing else; a helper process never exceeds its host lane's row, narrowed to what that one call needs; today every lane still shares one container environment, so this grid is a convention review and attestation hold to, made physical once per-lane cages arrive.

This isolation prevents:
- The implementor gaming its own review (it can't see evaluator feedback until the orchestrator routes it)
- The evaluator being biased by implementation approach (it can't see the code)
- The orchestrator making implementation decisions (it sequences, doesn't build)

Not all lanes are active in every flow. The evaluator lane is a future capability — documenting it here sets the architectural intent.

**Discovered work crosses lanes by record-and-file, never by the implementor writing the tracker.** Graft records concrete separable out-of-scope work found during build/review in `discovered_scope` and a per-issue file. Beep-boop files it autonomously, or the human files through graft's interactive gate, as a Backlog ticket. This is bottom-up source (b), appetite-gated by **Appetite for destruction** → Execution-discovered auto-create.


## Mechanism slot (`concurrency`)

The `concurrency` slot is a pure **mechanism**: it acts on faff's own graft and its vocabulary, with no paired adaptor or named-output set. Its contract is the action obligations below plus fixed gateway invariants it may never weaken. `ship` is a producer: it translates a foreign deploy result into `faff-contract:delivery-outcome` for graft Step 10 (see **Delivery outcome (fixed)**). This gateway owns the concurrency contract across swaps; occupants reference it per **Contract loading & conformance**, carrying only their dialect/implementation. The default SKILL.md describes how it meets the contract, never an authoritative copy.

### Build worker prompt

Pass one ordered unit to `dispatch prepare-build` as JSON on stdin: `{members:[{issue,tier?,confidence?}],run_id,run_dir,session_id}`. Use the partition's existing ratings (`build-tier` also works). Exit 2 stops dispatch. On success, log `effort_log` as not applied. Use the returned `agent_parameters` for Agent/Task. Put `dispatch` in the prompt as the explicit BuildDispatch along with the instruction to run `faff-graft` autonomously in its own worktree. Stamp these three clauses verbatim:

- "Foreground-to-terminal: run every gate/test/review step in the foreground; never end your turn without returning the TerminalToken per issue (or the sanctioned retry-later hold)."
- The **Voice clause** in `faff/references/kernel.md` under **Producer dispatch**.
- "Explicit review target: before any ad-hoc code-review fork, resolve this build's target via `faff review-target --resolve --issue <issue>` and pass it explicitly — never rely on an ambient-cwd default. `faff review-target --guard --issue <issue>` is the pre-review backstop: a non-zero exit means the ambient cwd is on the wrong branch — do not proceed with an un-targeted review."

### The `concurrency` slot contract (fixed)

Executes `/faff-beep-boop`'s build pass. Default `faffter-noon-concurrency-sequential`; override `faffter-dark-concurrency-parallel`. **Input:** the conflict-analysis partition for the current wave — `{ "independents": [...], "groups": [[...]] }` — plus the per-issue build action (invoke the `faff-graft` skill autonomously on `ISSUE-XX`) and the run ledger at `.faff/runs/<run-id>/run-ledger.json`.

**Obligations every `concurrency` occupant must honour:**

1. **Build every issue in the partition.** Independents and group members alike each reach a `/faff-graft` invocation. Nothing is skipped or deferred — that is the deferred-queue anti-pattern (see **Autonomous Mode Contract**), caught by `runcheck`.
2. **Serialise within a collision group, and require a *dependency* blocker to have merged — unless branch-stacking is opted in.** Members build in listed order, each only after the prior reaches a terminal state. "Terminal" ≠ "merged": `pr-open` / `parked` / `errored` are terminal but unmerged. A member that *depends on* an earlier member (declared blocker) is handled by the `graft.dependency_wait` knob (read once per pass via `faff config get graft.dependency_wait`; any value other than `stack` — including unset — resolves to `off`), which forks the disposition when the blocker landed **`pr-open`**:
   - **`off` (default) — park the dependent, byte-identical to today.** The blocker merged (`shipped`) ⇒ build the dependent; the blocker landed unmerged ⇒ **park the dependent** (cause `in-run blocker did not merge — <blocker-id> landed <state>`) rather than build it against a `main` missing the dependency. No stack anchor, no label, no worktree base override, no interlock leg.
   - **`stack` — build the dependent on the blocker's branch (FAFF-1077 branch-stacking).** When the blocker reached `pr-open`, do **not** park: resolve the blocker's PR + head branch (`gh pr view <pr> --json headRefName`) + **pinned tip commit SHA once** (`git rev-parse origin/<branch>` after a fetch), write and commit the stack anchor (`.faff/anchors/<run>/<dependent>/stack-parent.json`, `{dependent, parent_issue, parent_pr, parent_branch, parent_tip_sha, stacked_at}`; fail loud if the PR or branch is absent — a stack needs a forge parent), dispatch `faff-graft` for the dependent with `FAFF_WORKTREE_BASE_REF` set to **that same pinned SHA** (never a live `origin/<branch>` ref — the identical pinned commit anchors both the stack record and the worktree base, so the later `git rebase --onto <pinned-sha>` is provably correct), and apply the `faff-stacked` control label. The merge-order interlock (obligation 7's merge locus, via merge-gate's additive `dependency_gate` leg) then holds the dependent's merge until the blocker's PR merges. A blocker that landed **`parked`/`errored`** (never opened a PR) parks the dependent under `off` and `stack` alike — there is no branch to stack on. Git-only mode (no `origin`) has no forge PR to await, so `stack` degrades to `off` with a one-line warn and no base override is set.

   The two owner-park outcomes at the dependent's merge locus (the blocker's PR **closed without merging** ⇒ dead base; the rebase-onto-main **conflicts** ⇒ not an obvious fix) are enacted **here / in obligation 7's delivery-outcome routing**, never inside merge-gate — the merge gate only ever contributes the additive `dependency_gate` refusal (dependent stays `pr-open`) or, once the blocker merged, the `satisfied` leg. Same-surface-only members (shared files, no dependency) just serialise.
3. **Record every terminal outcome to the run ledger.** After custody, evidence and ground-truth reconciliation, run `faff run return-map --outcome TOKEN`. For `terminal`, record its `bucket` and append the issue to the named `annotation` array when present. Use the same bucket for the existing `issue-outcome` event path. For `merge-handoff`, complete obligation 7 before recording. `pre-admission` has no terminal bucket. Reconcile any admission contradiction or unknown token before writing. Keep existing writer and event ownership.
4. **Never weaken the merge gate.** AC-verified + CI-green + review `pass` — **and, under the L4 lights-out signal, a per-issue code-blind holdout `meets-spec` (the fourth floor condition, asserted last)** — is fixed here and in `/faff-graft`; a `concurrency` occupant controls *ordering and isolation* (and, for the parallel executor, rebase-before-merge re-validation), never *whether* the gate runs. **A lane that merges under the L4 signal MUST assert the holdout condition too** (obligation-4): a four-condition floor only one executor honours is worse than none (false assurance). At L1–L3 the floor is the three above, unchanged.
5. **Bracket every graft dispatch with integrity-digest custody — one continuous run-grain chain per orchestrator, for every occupant.** A dispatched build subagent is untrusted; the run-grain evidence it could tamper with (`run-ledger.json`, `corrective/`, `events.jsonl` — i.e. `correctiveIntegrityDirs(runDir)` + `--events`, always `--issue`-omitted) must be **detected** as tampered *before* the orchestrator consumes it for any scheduling decision. Every occupant holds **one** baseline over the whole member set for as long as the chain is open — never a per-dispatch baseline over a shared mutable set (a sibling's legitimate outcome, recorded while another unit is still in flight, would read as tampering against a stale per-dispatch baseline — the observed defect this rule exists to close): `faff integrity-digest snapshot --run-dir <run_dir> --events` opens the chain, the manifest held **in conversation context — never on disk** (a manifest on disk is one the subagent can read or replace, so verify always feeds it back via `--manifest -` stdin or inline JSON), and the run-grain check in obligation 6’s `faff dispatch verify-member` **on every subagent return**, before the token is reconciled or any outcome recorded. Branch on the exit: **exit 0** (`digest-verified`) → proceed exactly as today; **exit 1** (tamper) → **do not consume** the unit's run-dir evidence, park it (cause `integrity-digest tampered — <named paths>`, standard `faff-parked` label + comment, ledger bucket `parked`, and append `{issue, paths}` to a top-level `integrity_tampered` ledger array — the `review_outage_pending` precedent — for durable, loud run-summary surfacing; if git shows it already merged, the comment names both the paths and the merged PR); **exit 2** (verification unavailable — a subagent can *force* this, so it has substrate parity with tamper) → **do not consume**, park with cause `integrity-digest verification unavailable — <stderr first line>` (bucket `parked`, no `integrity_tampered` entry). There is **no** path from a non-zero exit to normal outcome recording. A lost baseline (compaction ate the manifest) is **not** tamper — surface the gap and discard evidence from every dispatch it spans. Re-snapshot before the trusted park writes. Park those returns with cause `integrity-digest verification unavailable: lost dispatch baseline`. Use the new chain for subsequent dispatches. **A trusted-side write landing inside an open bracket is permitted, never forbidden** (a detached writer — the sentry poller's `sentry abort` — writes from another process on its own schedule, so "forbid writes inside a bracket" is a rule addressed to nobody and unenforceable) — but only through the mandatory re-baseline sequence, always in this order: (1) **verify** the current baseline — non-zero exit routes to the park path above *before* the write, so a tamper already present is never laundered by a re-baseline; (2) **perform the write**, unchanged; (3) **post-write check** — verify the *old* baseline against disk again, requiring the named set to be **exactly** the members this write touched (a legitimate `events.jsonl` append still verifies clean under the prefix rule; any other member named is tamper); (4) **snapshot** → candidate new baseline; (5) **intended-content check**, split by write class. **Class A** (CLI-mediated: `events append --tokens`, `sentry abort`, `lights-out --resume`, `budget baseline`; `corrective author` is the `corrective/`-file analogue) — every one of these reports the sha256 of the bytes it wrote (`corrective author` the concrete case) — collapses steps (1)+(3)+(4)+(5) into **one atomic call, never hand-chained**: `faff integrity-digest rebaseline --run-dir <dir> --manifest - --written-path <path> --reported-sha256 <hash> [--events] [--issue <id>]`, the held baseline fed on stdin exactly as `verify` is — never a writable path. A single `diffAgainstManifest` of the held baseline against disk, taken *after* the write, does double duty: it proves the baseline still holds everywhere except the touched member (step 1's guarantee, now observed post-write rather than pre-write) and names exactly what moved (step 3), before the verb snapshots the candidate (step 4) and checks the touched member's recorded hash against the reported one (step 5). The verb mirrors `verify`'s never-silently-clean posture: `M′` reaches stdout **only** on a fully clean fold (exit 0); exit 1 (a non-written member also moved, the claimed write is not observed on disk, or an intended-content mismatch) and exit 2 (a hollow/wrong-grain baseline, a malformed `--reported-sha256`, or an unresolvable hasher) both emit **no** manifest — route either non-zero exit to the same park path this obligation already uses, never a hand re-derivation of the sequence; adopt the emitted `M′` as the new baseline only on exit 0. **Class B** (the orchestrator's own direct session edit of `run-ledger.json` — not a CLI call, so no before-hash exists for it, and the class the observed failure actually hit) stays hand-chained exactly as before — the edit **must be composed from the baseline-verified copy already held in context, never from a fresh disk read** (equivalently: hash the file immediately before composing and require it to equal the held baseline entry), so the window between the last verify and the write carries no unobserved read that could get absorbed into "intended" (a `rebaseline --held-copy` mode composing Class B from a supplied baseline-verified copy is a named extension point, not built here). Only a matching candidate replaces the baseline; a mismatch on either class is tamper → the exit-1 path. Event appends need no re-baseline — the prefix rule tolerates them. `run-ledger.json` keeps its whole-file byte comparison, always — no field scoping: a field carve-out would exempt exactly the live scheduling state (`outcomes`, `budget`, `stop_reason`) a laundering subagent most wants to edit. The verdict surfaces as the `digest-verified` trust class **only** — never presented, fed, or conflated with faff's separate outer-layer integrity-boundary authority (a distinct mechanism); merging the two is the lying-attestation failure the shipped CLI guards against. This is **detection ahead of consumption; it never changes obligation 4's merge floor.** Occupants carry only their own placement prose (when the chain opens/closes, how a park interacts with in-flight dispatches) and refer back here for the chain, the write sequence, and the Class A/B closing rules — never restate them.
6. **Verify each dispatched member before consuming its return.** The lane returns one `EvidenceReturn` per member alongside `TerminalToken{issue,outcome,pr}`, including in chains. Its final action is `faff evidence return --run-dir <run_dir> --issue <issue>`. Return the printed line verbatim, or JSON `null` on failure. Keep token and spend fields separate. The wire object contains exactly `issue`, `ac_checklist`, `review_verdict` and `human_only_acs`. Each digest contains `{present,sha256}`, with null for an absent file and 64 lowercase hex characters for a present file. Pass digests as data. File bodies can change in transit.

   The dispatcher runs `faff dispatch verify-member --run-dir <run_dir> --issue <dispatched member> --return '<EvidenceReturn or null>'` with its **own context-held** obligation-5 manifest on stdin. Take the issue from the dispatch. The command checks shared custody first, then compares the returned digests to the member's on-disk files. It writes nothing. If the dispatch baseline is lost, use obligation 5’s custody-gap recovery. A later snapshot cannot verify the earlier dispatch.

   - Exit 0: append a non-null `evidence_persisted` through obligation 5’s re-baseline sequence before reconciling. Matching absences require no entry. Discard the claim afterwards.
   - Exit 1 or 2: park with the printed `park_cause` and record only the reported `tampered_paths` using the obligation-5 ledger convention. For `scope: run`, apply obligation 5’s shared fault response without consuming member evidence. A missing or unreadable command result also takes that unavailable path. For `scope: member`, label, comment and record a parked bucket for that unit only. A malformed claim, an unavailable check or an absent claim alone adds no tamper entry.

   The lane still writes its AC and review files before anchoring them. Matching a digest detects changes after the lane wrote a file. The code-blind holdout independently evaluates its content. The human-only AC digest covers the run-dir copy used to mint the anchor. Merge-gate consumes the committed copy checked against the event stamp. Obligation 7 still re-verifies against the ledger immediately before merge. This obligation applies only to dispatched lanes.

7. **Run the merge above the cut — the dispatcher is the merge locus (relocation slice 2; dispatched lane only).** Slice 1 (obligation 6) moved verification of the merge-consumed evidence to the dispatcher; this slice moves the *merge itself* there, so the dispatcher-verified `ac-checklist.json` / `review-verdict.json` are the files the merge actually consumes (resolving slice 1's transitional in-lane-merge coupling — the dispatcher re-verifies them immediately before consuming them, on the trusted side). A dispatched build lane now ends at **PR-ready** — gates green, PR opened, evidence returned — and returns outcome `pr-ready`, performing **no** merge (no ship handoff, no `merge-gate`, no `merge-record.json`, no post-merge tail); one coherent invariant holds with obligation 6: **a lane returns `EvidenceReturn` ⟺ there is a dispatch cut ⟺ that lane does not merge; the dispatcher merges.** **Custody wiring — the dispatched-lane detective-custody producer that arms the dormant custody merge gate.** Once at pass start, **before the first dispatch**, the dispatcher emits the build-lane boundary — `faff lane-boundary emit --run-dir <run_dir> --lane build` — so the run reads `dispatched` (`laneBoundaryDispatchState`) and `evaluateCustody` becomes **required** for every merge in the run dir, while a `build` lane can never arm the evaluator cage (`laneBoundaryPromisesCage` stays keyed on `lane === "evaluator"`, so the widened vocabulary is dispatch-only, never a cage promise). A non-zero emit **parks the pass before any dispatch** — a half-wired run (boundary present, no threaded verdict) would refuse every merge. This is genuine **detective** custody (a trusted dispatcher verifying an *untrusted* lane's forge surface), never the interactive `--local` self-consistency stamp, and the verdict is never fed through `FAFF_INTEGRITY_BOUNDARY` (the two-basis discipline). For each member returning `pr-ready`, **strictly after** obligation 5's run-grain verify and obligation 6's evidence verify have both passed for it, the dispatcher — not the lane — first re-runs obligation 5's run-grain verify and then `faff evidence verify-return --against-ledger --run-dir <run_dir> --issue <issue>`, which compares the files on disk with the `evidence_persisted` entry the ledger already holds (a custody-protected source that survives compaction; a fresh hash at merge time would always agree and detect nothing); a non-zero exit of either parks the unit as obligation 6 does and **never merges**. Only then does it run the merge locus against the dispatcher-verified evidence: (a) assert the non-delegable integrity floor (AC-verified + CI-green + review `pass`, plus the L4 code-blind holdout `meets-spec`) — a floor miss never merges and records the deferral, never a silent skip; (b) run the merge-time ADR/PRDR-collision guard; **(b′) produce the per-issue custody verdict** — `faff integrity-digest verify --record-result <run_dir>/<issue>/custody-verdict.json --manifest - --events --issue-context <issue> --merge-state pre-merge --json` over **obligation 5's held run-grain baseline** (fed on stdin, never a fresh snapshot and never a disk path — the held-in-context baseline is the whole point of obligation 5), capturing `verdict_sha256`; **exit 1 (tamper) / exit 2 (verification-unavailable) → park the unit, never merge** (fail-closed — the written verdict is non-admitting, so even an attempted merge refuses; the custody gate fires instead of returning `{required:false}`), exit 0 (clean) → carry the two custody flags into (c); (c) invoke `slots.ship` (`--pr`/`--issue`/`--run-dir`/`--level` **plus `--custody-verdict <path>`/`--custody-verdict-sha256 <sha>` from (b′) on a clean verdict**; git-only: `--local`) and consume its `faff-contract:delivery-outcome` via `JSON.parse` → `faff contract delivery-outcome`; (d) on `shipped`, run the post-merge verification tail (`faff post-merge-check`) autonomously — `verified-fail` behaviour is unchanged (comment + `discovered-scope.json`, status stays `Done`, never revert). Complete `pr-ready` to a fixed obligation-3 bucket by routing that `delivery-outcome` (canonical semantics: `faff contract delivery-outcome --describe`) — a merge lands `shipped`, a delivery-precondition deferral leaves the PR open as `pr-open`, a merge/deploy error is `parked` + standard park comment; `pr-ready` is the lane's hand-off token, **never** a raw ledger bucket. The parallel executor runs this inside its existing rebase-before-merge serialisation, one member at a time (obligation 4's re-validation). **Interactive and autonomous-but-top-level graft have no dispatch cut above them and are out of scope** — they merge in-session exactly as today (the carve-out). This obligation **relocates the invocation, never the decision**: it never weakens obligation 4's merge floor. Occupants carry only their own placement prose (where in their return-handling this runs) and refer back here — never restate it.

**Output.** Every partition issue reaches a terminal state, all recorded in the ledger; control returns to beep-boop's wave drain. **Worktree isolation** (one worktree per build, never shared) is mandatory for any occupant that runs builds concurrently — see **Worktree policy**.
