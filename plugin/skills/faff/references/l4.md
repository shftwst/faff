# Faff gateway reference — L4 concurrency & evaluator

> Part of the faff gateway. Read on demand by the skills whose lane consumes it (see each skill's load-line). Cross-references of the form `gateway → **Section**` resolve against the kernel and all references pooled.

### Evaluator (external lane)

**Visibility:** Documentation, specification, stood-up environment (runtime access). **No codebase access.**
**Not concerned with:** How the code works. Only whether the delivered artefact satisfies the spec from a business-value perspective.

Quality control from the outside:
- Can the feature be exercised in the running environment?
- Does the behaviour match what the spec promised?
- Are acceptance criteria met from a user's perspective (not a code perspective)?
- Does the delivered value match the problem statement in WHY?

This lane is intentionally blind to implementation — it evaluates outcomes, not code. A passing evaluator signal means the feature works as specified regardless of how it's built.

### Lane isolation

The lanes have **controlled visibility by design**, not by accident:

| Lane | Codebase | Tracker | Spec | Environment | Human dialogue |
|---|---|---|---|---|---|
| Orchestrator | Read (context) | Full | Read | No | Yes |
| Implementor | Full read/write | No | Read | Local dev | No (via orchestrator) |
| Evaluator | **No** | No | Read | Runtime access | No (via orchestrator) |

| Secret class | Orchestrator | Implementor | Evaluator |
|---|---|---|---|
| Agent-engine credentials | Yes | Yes (incl. adversarial-review key, scoped to its helper process) | Yes (its runtime helper is itself an LLM process) |
| Forge credential | Yes | Yes | No |
| Tracker credential | Yes | No (host-session tool grant, no lane-held key) | No |
| Project runtime secrets | No | Yes (local dev) | No (gets synthetic credentials instead) |
| Synthetic SUT credentials | Transit only, never persisted | No | Yes (its runtime input) |
| Engine-context vars | Yes | Yes (local dev) | No (endpoint URLs only, never the engine) |
Secrets get the same treatment: the evaluator's complete visible set is an engine credential, the env-handle's contents, and the spec text — nothing else; a helper process never exceeds its host lane's row, narrowed to what that one call needs; today every lane still shares one container environment, so this grid is a convention review and attestation hold to, made physical once per-lane cages arrive.

This isolation prevents:
- The implementor gaming its own review (it can't see evaluator feedback until the orchestrator routes it)
- The evaluator being biased by implementation approach (it can't see the code)
- The orchestrator making implementation decisions (it sequences, doesn't build)

Not all lanes are active in every flow. The evaluator lane is a future capability — documenting it here sets the architectural intent.

**Discovered work crosses lanes by record-and-file, never by the implementor writing the tracker.** When the implementor (faff-graft) finds concrete, separable out-of-scope work while building or reviewing, it **records** it (returns `discovered_scope` + writes a per-issue file) — it does **not** create the ticket. The orchestrator (faff-beep-boop autonomously, or the human via faff-graft's interactive gate) **files** it as a Backlog ticket. This is bottom-up source (b) — execution-discovered work — the tributary that lets the backlog self-extend from *doing*, not only from declaration. Its filing is appetite-gated (see **Appetite for destruction** → Execution-discovered auto-create).


## Mechanism slot (`concurrency`)

The `concurrency` slot is a pure **mechanism** — it *performs an action* in the pipeline rather than producing a translatable artefact (`intake` produces a brief; the adaptors translate; methodology answers named outputs). A mechanism slot has **no paired adaptor** and **no named-output set**; its contract is the set of obligations its action must honour plus the fixed gateway invariants it may never weaken. (`ship` was formerly a mechanism here; it is now a **producer** that emits its `faff-contract:delivery-outcome` block, consumed by faff-graft Step 10 — see **Delivery outcome (fixed)** — because its occupant reads a *foreign* deploy tool's output and self-declares it onto the fixed outcomes. `concurrency` stays a mechanism: it drives faff's *own* graft, which already returns faff's vocabulary, so it has no foreign output to translate.) This section is the **canonical, gateway-owned contract** for `concurrency`, so it survives a swap — an occupant carries only its dialect/implementation and **refers back here** (per **Contract loading & conformance**), never an authoritative copy. The default occupant's `SKILL.md` documents *how the default* discharges the contract; it is not the source of the contract.

### The `concurrency` slot contract (fixed)

Executes `/faff-beep-boop`'s build pass. Default `faffter-noon-concurrency-sequential`; override `faffter-dark-concurrency-parallel`. **Input:** the conflict-analysis partition for the current wave — `{ "independents": [...], "groups": [[...]] }` — plus the per-issue build action (invoke the `faff-graft` skill autonomously on `ISSUE-XX`) and the run ledger at `.faff/runs/<run-id>/run-ledger.json`.

**Obligations every `concurrency` occupant must honour:**

1. **Build every issue in the partition.** Independents and group members alike each reach a `/faff-graft` invocation. Nothing is skipped or deferred — that is the deferred-queue anti-pattern (see **Autonomous Mode Contract**), caught by `runcheck`.
2. **Serialise within a collision group, and require a *dependency* blocker to have merged.** Members build in listed order, each only after the prior reaches a terminal state. "Terminal" ≠ "merged": `pr-open` / `parked` / `errored` are terminal but unmerged. A member that *depends on* an earlier member (declared blocker) builds **only if that blocker merged (`shipped`)**; if the blocker landed unmerged, **park the dependent** (cause `in-run blocker did not merge — <blocker-id> landed <state>`) rather than build it against a `main` missing the dependency. Same-surface-only members (shared files, no dependency) just serialise.
3. **Record every terminal outcome to the run ledger** the moment an issue lands, as one of the fixed buckets `shipped` / `superseded` / `pr-open` / `parked` / `errored` (see **`.faff/` logging directory** → Run ledger). Map `/faff-graft`'s caller-facing returns to buckets: **`pr-open-for-human` → `pr-open`**, **`superseded-done` → `superseded`** (the admitted build-time premise-superseded close-path; `superseded` is already in runcheck's accepted vocabulary), **`retry-later` → `parked`** (additionally append the issue id to the ledger's top-level `review_outage_pending` array, mirroring `review_adversarial_skipped`; no new bucket), others as themselves. **`pr-ready` is not a terminal outcome**: the dispatcher completes it to `shipped` / `pr-open` / `parked` via obligation 7 before recording — it is never written to the ledger as a raw bucket. Write the bucket, never the raw token, or `runcheck` flags it invalid.
4. **Never weaken the merge gate.** AC-verified + CI-green + review `pass` — **and, under the L4 lights-out signal, a per-issue code-blind holdout `meets-spec` (the fourth floor condition, asserted last)** — is fixed here and in `/faff-graft`; a `concurrency` occupant controls *ordering and isolation* (and, for the parallel executor, rebase-before-merge re-validation), never *whether* the gate runs. **A lane that merges under the L4 signal MUST assert the holdout condition too** (obligation-4): a four-condition floor only one executor honours is worse than none (false assurance). At L1–L3 the floor is the three above, unchanged.
5. **Bracket every graft dispatch with integrity-digest custody — one continuous run-grain chain per orchestrator, for every occupant.** A dispatched build subagent is untrusted; the run-grain evidence it could tamper with (`run-ledger.json`, `corrective/`, `events.jsonl` — i.e. `correctiveIntegrityDirs(runDir)` + `--events`, always `--issue`-omitted) must be **detected** as tampered *before* the orchestrator consumes it for any scheduling decision. Every occupant holds **one** baseline over the whole member set for as long as the chain is open — never a per-dispatch baseline over a shared mutable set (a sibling's legitimate outcome, recorded while another unit is still in flight, would read as tampering against a stale per-dispatch baseline — the observed defect this rule exists to close): `faff integrity-digest snapshot --run-dir <run_dir> --events` opens the chain, the manifest held **in conversation context — never on disk** (a manifest on disk is one the subagent can read or replace, so verify always feeds it back via `--manifest -` stdin or inline JSON), and `faff integrity-digest verify --run-dir <run_dir> --events --manifest - --json` **on every subagent return**, before the token is reconciled or any outcome recorded. Branch on the exit: **exit 0** (`digest-verified`) → proceed exactly as today; **exit 1** (tamper) → **do not consume** the unit's run-dir evidence, park it (cause `integrity-digest tampered — <named paths>`, standard `faff-parked` label + comment, ledger bucket `parked`, and append `{issue, paths}` to a top-level `integrity_tampered` ledger array — the `review_outage_pending` precedent — for durable, loud run-summary surfacing; if git shows it already merged, the comment names both the paths and the merged PR); **exit 2** (verification unavailable — a subagent can *force* this, so it has substrate parity with tamper) → **do not consume**, park with cause `integrity-digest verification unavailable — <stderr first line>` (bucket `parked`, no `integrity_tampered` entry). There is **no** path from a non-zero exit to normal outcome recording. A lost baseline (compaction ate the manifest) is **not** tamper — surface the custody gap loudly, re-snapshot to restart the chain, and continue. **A trusted-side write landing inside an open bracket is permitted, never forbidden** (a detached writer — the sentry poller's `sentry abort` — writes from another process on its own schedule, so "forbid writes inside a bracket" is a rule addressed to nobody and unenforceable) — but only through the mandatory re-baseline sequence, always in this order: (1) **verify** the current baseline — non-zero exit routes to the park path above *before* the write, so a tamper already present is never laundered by a re-baseline; (2) **perform the write**, unchanged; (3) **post-write check** — verify the *old* baseline against disk again, requiring the named set to be **exactly** the members this write touched (a legitimate `events.jsonl` append still verifies clean under the prefix rule; any other member named is tamper); (4) **snapshot** → candidate new baseline; (5) **intended-content check**, split by write class. **Class A** (CLI-mediated: `events append --tokens`, `sentry abort`, `lights-out --resume`, `budget baseline`; `corrective author` is the `corrective/`-file analogue) — every one of these reports the sha256 of the bytes it wrote (`corrective author` the concrete case) — collapses steps (1)+(3)+(4)+(5) into **one atomic call, never hand-chained**: `faff integrity-digest rebaseline --run-dir <dir> --manifest - --written-path <path> --reported-sha256 <hash> [--events] [--issue <id>]`, the held baseline fed on stdin exactly as `verify` is — never a writable path. A single `diffAgainstManifest` of the held baseline against disk, taken *after* the write, does double duty: it proves the baseline still holds everywhere except the touched member (step 1's guarantee, now observed post-write rather than pre-write) and names exactly what moved (step 3), before the verb snapshots the candidate (step 4) and checks the touched member's recorded hash against the reported one (step 5). The verb mirrors `verify`'s never-silently-clean posture: `M′` reaches stdout **only** on a fully clean fold (exit 0); exit 1 (a non-written member also moved, the claimed write is not observed on disk, or an intended-content mismatch) and exit 2 (a hollow/wrong-grain baseline, a malformed `--reported-sha256`, or an unresolvable hasher) both emit **no** manifest — route either non-zero exit to the same park path this obligation already uses, never a hand re-derivation of the sequence; adopt the emitted `M′` as the new baseline only on exit 0. **Class B** (the orchestrator's own direct session edit of `run-ledger.json` — not a CLI call, so no before-hash exists for it, and the class the observed failure actually hit) stays hand-chained exactly as before — the edit **must be composed from the baseline-verified copy already held in context, never from a fresh disk read** (equivalently: hash the file immediately before composing and require it to equal the held baseline entry), so the window between the last verify and the write carries no unobserved read that could get absorbed into "intended" (a `rebaseline --held-copy` mode composing Class B from a supplied baseline-verified copy is a named extension point, not built here). Only a matching candidate replaces the baseline; a mismatch on either class is tamper → the exit-1 path. Event appends need no re-baseline — the prefix rule tolerates them. `run-ledger.json` keeps its whole-file byte comparison, always — no field scoping: a field carve-out would exempt exactly the live scheduling state (`outcomes`, `budget`, `stop_reason`) a laundering subagent most wants to edit. The verdict surfaces as the `digest-verified` trust class **only** — never presented, fed, or conflated with faff's separate outer-layer integrity-boundary authority (a distinct mechanism); merging the two is the lying-attestation failure the shipped CLI guards against. This is **detection ahead of consumption; it never changes obligation 4's merge floor.** Occupants carry only their own placement prose (when the chain opens/closes, how a park interacts with in-flight dispatches) and refer back here for the chain, the write sequence, and the Class A/B closing rules — never restate them.
6. **Persist + verify the returned per-issue evidence — the dispatcher is the writer of record (relocation slice 1; dispatched lane only).** The build lane *returns* its AC-verification result and the reviewer's extraction JSON **alongside — never inside — the `TerminalToken{issue,outcome,pr}`**: the token stays `{issue,outcome,pr}` (the "no token/spend field, ever" invariant is untouched) and the evidence rides as a sibling `EvidenceReturn` field on the same structured terminal-return channel, never the free-text transcript (the `discovered_scope` precedent). One `EvidenceReturn { issue, ac_checklist:{present,body}, review_verdict:{present,body} }` per member (a chain returns one per member), with `present==false ⟺ body==null`, and the lane returning each present file's **raw bytes** — never a parsed-then-re-serialized object, since a key-order/whitespace/escaping difference would false-park a clean build. On each subagent return — **after** obligation 5's run-grain verify and **before** the token is reconciled or any outcome recorded — the dispatcher runs, for each of `ac-checklist.json` / `review-verdict.json`: (a) if the returned `present` disagrees with whether the file exists on disk → **park**; (b) if present, if the returned raw bytes' leaf sha256 (the same primitive `integrity-digest` uses — no new CLI surface required) ≠ the on-disk file's leaf sha256 → **park**; (c) on agreement, (re)write the run-dir path from the returned body as the orchestrator-authored copy and append an `evidence_persisted {issue, ac_sha256?, review_verdict_sha256?}` ledger entry **through obligation 5's mandatory re-baseline write sequence** (the ledger is a bracketed member; the per-issue file itself is not). A legitimately-absent file (`present:false` matching disk-absent — a pre-worktree skip, a `retry-later` that wrote no `review-verdict.json`, an early park/errored) neither parks nor persists. A park here reuses obligation 5's **exit-1 path verbatim** — cause `evidence-return mismatch — <issue>/<file> (<presence disagreement|returned copy ≠ on-disk copy>)`, `faff-parked` + comment, bucket `parked`, `{issue,paths}` appended to the `integrity_tampered` array — and is **unit-scoped**: a per-issue evidence mismatch parks only that unit and never halts-and-drains a wave (obligation 5's run-grain chain guards the shared substrate, and its own tamper response cannot stop in-flight merges either, so escalating buys little while over-scoping is a denial-of-service amplifier). **Honest scope:** this moves the *writer of record* for these two files above the dispatch cut and adds tamper-between-write-and-return detection; it does **not** make their *content* independent of the authoring lane — a lane that authors both the on-disk copy and the returned copy identically passes, so content-independence stays the code-blind holdout's job (obligation 4), never claimed here. **Post-relocation (slice 2):** the lane keeps its own AC/review writes because the Step-9b anchor reads them pre-return, but the merge no longer runs in-lane — the dispatcher-persisted copy is the orchestrator-authored copy the dispatcher-run merge consumes (obligation 7) and the source for post-return reconciliation/audit. This is **write-authority relocation + detection ahead of consumption; it never changes obligation 4's merge floor.** Occupants carry only their own placement prose (where in their return-handling the check runs) and refer back here — never restate it. **Interactive top-level graft has no dispatch cut above it and is out of scope (the carve-out); this obligation binds only a dispatched build lane.**

7. **Run the merge above the cut — the dispatcher is the merge locus (relocation slice 2; dispatched lane only).** Slice 1 (obligation 6) moved the *writer of record* for the merge-consumed evidence to the dispatcher; this slice moves the *merge itself* there, so the dispatcher-persisted `ac-checklist.json` / `review-verdict.json` become the copy the merge actually consumes (resolving slice 1's transitional in-lane-merge coupling — the dispatcher writes them last, immediately before consuming them, on the trusted side). A dispatched build lane now ends at **PR-ready** — gates green, PR opened, evidence returned — and returns outcome `pr-ready`, performing **no** merge (no ship handoff, no `merge-gate`, no `merge-record.json`, no post-merge tail); one coherent invariant holds with obligation 6: **a lane returns `EvidenceReturn` ⟺ there is a dispatch cut ⟺ that lane does not merge; the dispatcher merges.** **Custody wiring — the dispatched-lane detective-custody producer that arms the dormant custody merge gate.** Once at pass start, **before the first dispatch**, the dispatcher emits the build-lane boundary — `faff lane-boundary emit --run-dir <run_dir> --lane build` — so the run reads `dispatched` (`laneBoundaryDispatchState`) and `evaluateCustody` becomes **required** for every merge in the run dir, while a `build` lane can never arm the evaluator cage (`laneBoundaryPromisesCage` stays keyed on `lane === "evaluator"`, so the widened vocabulary is dispatch-only, never a cage promise). A non-zero emit **parks the pass before any dispatch** — a half-wired run (boundary present, no threaded verdict) would refuse every merge. This is genuine **detective** custody (a trusted dispatcher verifying an *untrusted* lane's forge surface), never the interactive `--local` self-consistency stamp, and the verdict is never fed through `FAFF_INTEGRITY_BOUNDARY` (the two-basis discipline). For each member returning `pr-ready`, **strictly after** obligation 5's run-grain verify and obligation 6's evidence persist + digest-verify have both passed for it, the dispatcher — not the lane — runs the merge locus against the dispatcher-persisted evidence: (a) assert the non-delegable integrity floor (AC-verified + CI-green + review `pass`, plus the L4 code-blind holdout `meets-spec`) — a floor miss never merges and records the deferral, never a silent skip; (b) run the merge-time ADR/PRDR-collision guard; **(b′) produce the per-issue custody verdict** — `faff integrity-digest verify --record-result <run_dir>/<issue>/custody-verdict.json --manifest - --events --issue-context <issue> --merge-state pre-merge --json` over **obligation 5's held run-grain baseline** (fed on stdin, never a fresh snapshot and never a disk path — the held-in-context baseline is the whole point of obligation 5), capturing `verdict_sha256`; **exit 1 (tamper) / exit 2 (verification-unavailable) → park the unit, never merge** (fail-closed — the written verdict is non-admitting, so even an attempted merge refuses; the custody gate fires instead of returning `{required:false}`), exit 0 (clean) → carry the two custody flags into (c); (c) invoke `slots.ship` (`--pr`/`--issue`/`--run-dir`/`--level` **plus `--custody-verdict <path>`/`--custody-verdict-sha256 <sha>` from (b′) on a clean verdict**; git-only: `--local`) and consume its `faff-contract:delivery-outcome` via `JSON.parse` → `faff contract delivery-outcome`; (d) on `shipped`, run the post-merge verification tail (`faff post-merge-check`) autonomously — `verified-fail` behaviour is unchanged (comment + `discovered-scope.json`, status stays `Done`, never revert). Complete `pr-ready` to a fixed obligation-3 bucket by routing that `delivery-outcome` (canonical semantics: `faff contract delivery-outcome --describe`) — a merge lands `shipped`, a delivery-precondition deferral leaves the PR open as `pr-open`, a merge/deploy error is `parked` + standard park comment; `pr-ready` is the lane's hand-off token, **never** a raw ledger bucket. The parallel executor runs this inside its existing rebase-before-merge serialisation, one member at a time (obligation 4's re-validation). **Interactive and autonomous-but-top-level graft have no dispatch cut above them and are out of scope** — they merge in-session exactly as today (the carve-out). This obligation **relocates the invocation, never the decision**: it never weakens obligation 4's merge floor. Occupants carry only their own placement prose (where in their return-handling this runs) and refer back here — never restate it.

**Output.** Every partition issue reaches a terminal state, all recorded in the ledger; control returns to beep-boop's wave drain. **Worktree isolation** (one worktree per build, never shared) is mandatory for any occupant that runs builds concurrently — see **Worktree policy**.
