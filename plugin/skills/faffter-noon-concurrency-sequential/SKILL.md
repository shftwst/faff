# faffter-noon-concurrency-sequential

The default `concurrency` executor runs `/faff-beep-boop`'s conflict-analysis partition **sequentially**, one `/faff-graft` at a time. No concurrent worktrees, merge races or cap to tune. Use `faffter-dark-concurrency-parallel` when the project can absorb concurrent worktrees.

```yaml
slots:
  concurrency: faffter-noon-concurrency-sequential   # the default — explicit for clarity
```

## When it runs

Invoked by `/faff-beep-boop`'s build pass (full pipeline step 6 and explicit-list loop) as the configured `concurrency` skill, default when unset. A **mechanism** slot with no paired adaptor: it executes rather than produces or translates.

## The slot contract

When standalone, Read the sibling `faff/references/kernel.md` (the shared kernel) first, then the lane references this executor consumes — `faff/references/build.md` (Worktree policy) and `faff/references/l4.md` (the concurrency contract, Mechanism slot, and Evaluator lane).

The `concurrency` slot contract is **fixed in the gateway** — see `faff/references/l4.md` → **Mechanism slot (`concurrency`)** → _The `concurrency` slot contract_. It defines every occupant's input (partition + per-issue build action + run ledger) and seven obligations — (1) build every partition issue, (2) serialise within a collision group and require a *dependency* blocker to have **merged** (else park the dependent), (3) record every terminal outcome to the run ledger using the fixed buckets, (4) never weaken the merge gate — AC + CI-green + review `pass`, **plus the L4 per-issue code-blind holdout `meets-spec`**, (5) bracket every graft dispatch with integrity-digest custody (snapshot, verify on return, tamper/unavailable parks the unit), (6) persist + verify the returned per-issue AC/review evidence, parking the unit on a mismatch, (7) run the merge above the cut — for each `pr-ready` member the dispatcher, not the lane, runs the merge locus and records the resulting bucket. This skill **refers back** to that contract; the recap here is non-normative and the gateway wins on any conflict. What follows is only *how this default discharges it*.

## How the default runs it

Strictly one issue at a time, no worktree concurrency:

1. Order the work: independents first (in the order beep-boop supplied — already priority → chainable-unlock-value, reframed by any methodology), then each collision group as a contiguous block (members in listed order).
2. For each unit, use one build subagent for the independent issue or whole ordered collision chain. Before a Sentry corrective re-dispatch, run `faff corrective check --run-dir <run_dir> --issue <issue> --manifest -` with the context-held, re-baselined Class-A custody manifest on stdin (obligation 5). A pre-authoring manifest false-refuses; a fresh snapshot cannot verify the preceding dispatch. Skip this check on ordinary builds.
   - A mandate of `empty` or `indeterminate` parks the unit before dispatch. For a `narrowed` mandate, attach only the verified `constraints` to the returned BuildDispatch when the disposition is `trusted` or `custody-trusted`. For `channel-D` or `refuse`, omit constraints and log any refusal.
   - Run `faff dispatch prepare-build --executor sequential` and apply **Build worker prompt** in `faff/references/l4.md`, including its foreground-to-terminal clause. Block on the Agent/Task call (`run_in_background: false`). Each member returns a TerminalToken and EvidenceReturn. Graft stops at PR-ready. Discard the worker context and merge each ready member here under obligation 7. Never run the build inline via the Skill tool.
3. **Reconcile, then record.** Read the unit's `.faff/runs/<run-id>/ISSUE-XX/` artifacts + git ground truth (PR / CI / merge state) and write the terminal outcome to the run ledger yourself — the token is the subagent's *claim*; disk + git are the *truth* on any disagreement (per "verify subagent claims against ground truth"). Never parse the subagent's free-text transcript for the outcome. A subagent that returns no token triggers the same ground-truth reconciliation, not a blind park.
4. When the list is exhausted, return to beep-boop.

**Integrity-digest bracket (obligation 5 — placement here).** This executor opens **at most one** bracket at a time — the chain is the same shared one obligation 5 defines, just never overlapping here. Per unit: **snapshot at the top of step 2**, immediately before the dispatch (after any pre-dispatch orchestrator write such as the `constraints` corrective check), holding the manifest in context; then **verify as the first action of step 3**, immediately on return, before the token is reconciled or anything is recorded, and the step-3 ledger/event write follows through the gateway's mandatory re-baseline sequence like any other trusted-side write. Foreground-blocking does **not** make this executor exempt from a mid-bracket write landing unbidden: the detached sentry poller's `sentry abort` runs in another process on its own schedule and can write the ledger while a dispatch is still in flight, so a re-baseline is sometimes needed here too — never assume zero. On exit 0 proceed to reconcile-then-record as above and discard the manifest; on exit 1 (tamper) or exit 2 (verification unavailable) run the shared park — do **not** reconcile the unit's run-dir evidence. Member set, the chain, the write sequence, exit outcomes, and park mechanics are all the gateway's — see obligation 5.

**Per-issue evidence verify (obligation 6 — placement here).** Runs as the **second action of step 3**, immediately after the obligation-5 verify above and **before** reconcile-then-record: for the unit's member, take the lane's returned `EvidenceReturn` (the sibling field it returned alongside the token — the token stays `{issue,outcome,pr}`) and run `faff evidence verify-return` on it. On agreement, append the printed `evidence_persisted` ledger entry through the same re-baseline sequence the step-3 write already uses; on a mismatch or malformed return, run the park, unit-scoped (this executor builds one unit at a time, so there is no wave to halt regardless). The check, the `EvidenceReturn` shape, the exit branches, and the honest scope are all the gateway's — see obligation 6.

**Merge above the cut (obligation 7 — placement here).** A clean build returns `pr-ready`, not `shipped` — the merge no longer runs in the lane. **Once at pass start, before the first dispatch, this executor emits the build-lane boundary** (`faff lane-boundary emit --run-dir <run_dir> --lane build`) so the run reads `dispatched` and custody is required for every merge; a non-zero emit parks the pass before any dispatch. As the **third action of step 3**, immediately after the obligation-6 verify and before recording the terminal bucket, this executor runs obligation 7's pre-merge `faff evidence verify-return --against-ledger` re-verify and then the merge locus for a `pr-ready` member against the dispatcher-verified `ac-checklist.json` / `review-verdict.json`: assert the floor, run the ADR/PRDR-collision guard, **produce the per-issue detective-custody verdict over obligation 5's held run-grain baseline and thread `--custody-verdict`/`--custody-verdict-sha256` into the ship call** (a tamper/unavailable verdict parks the unit, never merges), invoke `slots.ship` (`--pr`/`--issue`/`--run-dir`/`--level`; git-only `--local`) and route its `faff-contract:delivery-outcome`, and on `shipped` run the post-merge tail — then record the resulting `shipped` / `pr-open` / `parked` bucket. Because builds are strictly serial here, each merge sees `main` as the prior merge left it — no rebase step is needed (obligation 7's rebase note is the parallel executor's). Any other returned token records as today, no merge. The boundary emit, the custody verdict, the floor, the routing, the ship handoff, and the fixed bucket completion are all the gateway's — see obligation 7.

Record the reconciled bucket per concurrency obligation 3. Complete `pr-ready` at the dispatcher merge first (obligation 7). `shipped` and `pr-open` require a PR. The outcome `superseded-done` has no PR and needs `<run-dir>/<issue>/supersession.json`. Queue and budget dispositions belong to the orchestrator. Resolve `claimed-by-peer` before dispatch.

Between dispatches the orchestrator ticks `faff heartbeat "$run_dir"`. During a build the subagent ticks the run named in `BuildDispatch`. The CLI refreshes the heartbeat sidecar and preserves the owner stamp.

Before the next dispatch, merge the current unit (obligation 7) or record its park. Each build sees the prior merge's `main`, requiring no rebase or merge-race handling. Dependency handling uses `graft.dependency_wait` (obligation 2), resolved once per pass via `faff config get graft.dependency_wait -d`:

- **`off` (default):** a dependent whose in-group blocker terminated **unmerged** is parked, not built — it can't build on a `main` that's missing its dependency. Byte-identical to today. Throughput is the cost; safety and simplicity are the payoff.
- **`stack`:** a dependent whose blocker landed **`pr-open`** is stacked, not parked — resolve the blocker's PR + head branch + **pinned tip SHA once**, write and commit the `stack-parent.json` anchor, dispatch the dependent's graft with `FAFF_WORKTREE_BASE_REF` set to **that same pinned SHA**, and apply the `faff-stacked` label (mechanics per obligation 2). The dependent builds and opens its PR on the blocker's branch while the blocker's PR is in review. At its merge locus (obligation 7) merge-gate's additive `dependency_gate` leg refuses the merge until the blocker's PR merges (the dependent stays `pr-open`); once the blocker merges, the merge locus runs the bounded `git rebase --onto <pinned-sha>` before merging. The two owner-park outcomes — blocker PR **closed-unmerged** (dead base) and a rebase **conflict** — are enacted **here** (park the dependent, `reconsider:human`) from the merge-gate result's surfaced park intent, never inside merge-gate. A blocker that landed `parked`/`errored` parks the dependent under both knob values (no branch to stack on); git-only mode degrades `stack` to `off`.

**Resume-from-ledger.** Re-dispatch an `admitted` issue lacking an `outcomes` entry (compaction mid-build or stall mid-review) as a fresh build subagent. Graft idempotently re-attaches to its worktree/branch/PR and reads `review-progress`, skipping completed Phase-1 only under the diff-identity guard and skipping completed Phase-2. The orchestrator holds no build-specific context. All review compute remains **inside the re-dispatched subagent**; the orchestrator never invokes `review-call.mjs` or runs a review phase.

## Rules

- This is the **minimum** executor. A richer occupant (`faffter-dark-concurrency-parallel`) may run independents concurrently — but must still honour the seven slot-contract obligations above.
- No WIP cap applies to autonomous runs (the WIP cap is a human-flow concept — see the methodology slot). Sequential execution is a *safety/simplicity* choice, not a throttle.
- It never parks an issue for being "later in the queue" — sequencing is not deferral. Each issue runs; `/faff-graft` decides its terminal state.
- **`TerminalToken` stays `{ issue, outcome, pr }` — no token/spend field, ever.** The build subagent never measures its own token spend (its worktree cwd would mis-resolve the transcript root, and an in-subagent measure would return the whole-run cumulative, not its delta) and never writes `events.jsonl` (the orchestrator is the **sole** writer — an unlocked `seq` line-count can't tolerate a second writer). Per-subagent four-class spend is captured by the orchestrator's own `issue-outcome --tokens` emission on return, pinned to the run's `measure_root` + session id — not by widening this token. This orchestrator-sole-writer posture for `events.jsonl` / `run-ledger.json` is the **evidence class** of gateway → **Run-artifact write authority**; `events.jsonl` keeps its prefix-preserving carve-out (Decision 5).
