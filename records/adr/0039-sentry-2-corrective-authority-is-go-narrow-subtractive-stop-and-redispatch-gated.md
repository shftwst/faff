# ADR 0039 — Sentry-2 corrective authority is GO-narrow: subtractive stop-and-redispatch, gated on artifact integrity

- **Status:** Accepted
- **Date:** 2026-07-03
- **Issue:** FAFF-278

## Context

Sentry-1 (ADR-0034) shipped detection + a hard kill-switch that is un-subvertable *by construction*: the supervised build subagent returns only a terminal token and has no write-path to the orchestrator surface Sentry reads, so declining the next dispatch is a channel the watched agent cannot touch. Sentry-1 deliberately deferred *corrective* authority — the power to re-park / re-spec / constrain-and-continue rather than only halt — because a correction seems to require writing back **into** the supervised lane, reopening exactly the subversion surface the hard stop avoids. Three research-shaped questions were carried: the corrective-redirect channel, per-run vs concurrent-fleet supervision, and who-watches-the-watcher.

This decision is the outcome of the FAFF-278 **spike** — a bounded, human-supervised investigation whose deliverable is a recorded decision, not a shipped mechanism (the FAFF-263 / ADR-0029 precedent shape: name the decisive risk, gather evidence, prefer a narrow boundary over binary GO/NO-GO, name caveats and costed follow-ups). Method: threat-model four candidate channels against the 13 constraints extracted from ADR-0034, the concurrency executors, the trusted-spec carve-out, and the shipped sentry tests (pass 1); adversarially refute the survivors with an independent model, using a live-write-back channel as a planted canary (pass 2); mechanically confirm the shipped substrate on the existing forced-abort fixtures (pass 3). The full refutation log is in the spike record.

The load-bearing observation is that faff **already** performs every redirect-shaped act safely today — mid-build respec, park→re-enter, abort→resume — and all of them happen **while the supervised agent is not running**, through orchestrator-lane artifacts. So the real question is not "how do we write into a running lane" (we never should) but "can a *machine-authored* corrective input, consumed at the next dispatch, be trusted — and how far may it go?".

## Decision

**At L4, Sentry-2 corrective authority is GO-narrow, not full GO.** It is admitted as **Channel A** — *stop-and-redispatch with a machine-authored corrective input* — subject to three binding limits and one load-bearing precondition:

1. **Subtractive width only.** A corrective input may only *narrow* the supervised agent's mandate (park with cause, forbid a named surface, tighten a threshold, de-scope to a subset of the already-human-gated spec). This is the write-abstention safety template: safety comes from what the machine structurally *cannot* do — grant authority. **Additive** inputs (amend the WHAT, add scope, redirect the goal) have no human-gated provenance and route to **park / needs-human**, exactly as graft's respec already parks on any genuinely open decision. The trusted-spec carve-out covers human-gated content only and is **not** widened by this decision.

2. **Orchestrator-lane authoring, dispatch-boundary consumption.** Every corrective write happens while the supervised agent is dead (post-abort) or before it exists (pre-dispatch); the input is authored from the closed orchestrator surface (events.jsonl / run-ledger / budget / heartbeat) and consumed by the orchestrator's own resume-from-ledger at the next dispatch. No message path into a running lane is created — that would fire ADR-0034's isolation revisit trigger by construction.

3. **Empty-mandate degrades to park.** A subtractive constraint that contradicts the spec narrows the mandate to ∅; the re-dispatch must **detect this before dispatching and park**, never spin.

4. **Load-bearing precondition — corrective-artifact integrity.** The adversarial pass surfaced an **unmitigated break**: inside the container the build subagent shares uid and filesystem with the orchestrator's on-disk artifacts, so it can **forge** a corrective artifact. The shipped guard (terminal-token-only return) is *context* isolation and does **not** cover a new on-disk file. Channel A is therefore admitted **conditional on** an integrity mechanism that does not exist today — either a **read-only mount** of the corrective-artifact / run-ledger directory for the build subagent, or **orchestrator-verified signatures** on corrective artifacts checked before consumption. This is a container-fs-boundary question (co-bound to FAFF-42 / ADR-0010), assert-don't-implement — not faff prose.

**Channels rejected:** *Channel B* (a constraint file consulted mid-run) — refuted: under the shipped model graft runs *inside* the build subagent, so a mid-run constraint is self-enforced by the party being corrected, and relies on a derailed agent's cooperation; its sound residue (an orchestrator-consulted artifact at dispatch boundaries) just *is* Channel A. *Channel C* (live write-back into the running lane) — refuted, and held as the pass-2 canary: the independent skeptic correctly refused to pass it ("can race with the lane's execution → corrupted state"), confirming the review was calibrated. *Channel D* (tracker-mediated human relay) — the shipped baseline; it remains the fallback whenever a correction is not purely subtractive.

**Per-run vs fleet: per-run at v1.** Fleet supervision is deferred behind the parallel executor's unresolved multi-writer heartbeat/outcome contention (a fleet-level corrective artifact would add a new shared-mutable-state write surface); admissible only once the dedicated single-value heartbeat-file decoupling lands.

**Who-watches-the-watcher: a failure-mode register composing shipped precedents, no new lane.** Every Sentry failure must fail *open-to-human*: false-positive kill is resumable + visible (`aborted-resumable`); missed derailment is backstopped by budget spend/time + run-done's floor; a wedged/dead watcher is caught by L4's fail-closed evaluator-down handling; forged inputs are dropped by the closed allowlist (the AC5 normalizer, to be extended to the corrective-authoring path). A dedicated watcher-of-watchers lane is rejected for v1 (infinite regress; assert-don't-implement).

This ADR also **corrects a standing mis-reference**: the forbidden-side-effect *signal producer* Sentry consumes is the effects ledger (FAFF-106, `faff effects`), not FAFF-42. FAFF-42 / the container is the **blast-radius boundary** the un-subvertability claim is co-bound to — the same boundary that owns the integrity precondition above.

## Consequences

- **No production intervention code ships from FAFF-278.** The intervention ladder stays `continue | pause | abort`; the `test/sentry.test.mjs` AC6 no-`correct` guard still passes. The spike lands as docs (this ADR + the refutation log) only. A `correct` rung is added only by a future build ticket that consciously extends AC6.
- **The GO is provisional.** The probe proved the substrate (shipped abort-resumable guarantees, the AC5 detection-input allowlist) on fixtures; it did **not** exercise a real derailed run. Live-run validation is an outstanding evidence item, not a settled claim.
- **A residual pass 2 did not attack: steering-by-sequential-narrowing.** The refutation attacked a *single* subtractive input escalating into additive effect (not a break); it did not attack a *sequence* of individually-subtractive inputs across successive re-dispatches steering the build toward a machine-preferred implementation path — additive-in-effect over time. This is pinned as an explicit concern for the Channel A build (FAFF-326): every corrective input must cite the derailment verdict that triggered it, so the cumulative constraint set on an issue is auditable and a steering pattern is visible rather than silent.
- **The forge finding has a blast radius beyond corrective authority — flag on ADR-0034.** The adversarial pass found the forge risk while attacking the *corrective* artifact, but its root cause (build lane shares uid + fs with the orchestrator's on-disk surface inside the container) also touches Sentry-1's **detection** claim. ADR-0034's un-subvertability rests on two legs: the terminal-token context isolation *and* the closed-allowlist normalizer (AC5) that drops foreign fields before any predicate sees them. AC5 is proven to drop *injected stray fields* — but it does not obviously protect the **load-bearing ledger content itself** (the `outcomes` array, attempt counts) that the thrash and budget predicates read. A build lane that can rewrite `run-ledger.json` content could, in principle, suppress a detection signal (e.g. fake a `shipped` outcome to mask thrash). This does **not** overturn ADR-0034 — the reconcile-against-git-truth posture and the container boundary bound the worst case — but it means the **same integrity precondition** (read-only ledger mount / orchestrator-verified writes) that gates corrective authority is plausibly load-bearing for detection too under a shared-fs container. This strengthens rather than weakens the direction: the integrity mechanism is a shared precondition, not a corrective-authority tax. Re-examining ADR-0034 under the shared-fs model is costed follow-up 0 below.
- **Costed follow-ups (in dependency order, filed):**
  0. **Re-examine ADR-0034 detection un-subvertability under the shared-fs container model** — **FAFF-324**; distinguish injected-field forgery (AC5-covered) from ledger-content forgery (not obviously covered).
  1. **Corrective-artifact integrity mechanism** (the precondition) — **FAFF-325**; read-only ledger mount or orchestrator-verified signatures; co-bound to the FAFF-42 / container boundary. *Blocks FAFF-326.*
  2. **Build Channel A subtractive corrective authority** — **FAFF-326**; the corrective-input schema, orchestrator-lane authoring path, re-dispatch consumption, empty-mandate degrade-to-park, the AC5-shaped no-foreign-authorship test, and the cite-the-triggering-verdict rule (the steering-audit residual above); extends `SIGNAL_TRIP_INTERVENTION` and the AC6 guard.
  3. **Fleet supervision** — **FAFF-327**; behind the single-value heartbeat-file decoupling.
  4. **Live-run validation** — **FAFF-328**; a real derailed-run trial to discharge the provisional-GO caveat.
- **Downstream wiring is unblocked to plan around the boundary.** FAFF-312's run-governance model can treat corrective authority as a known-shape future rung (subtractive, dispatch-boundary, integrity-gated) rather than an open question; it still ships stop-only until the follow-ups land.
- **If container isolation ever weakens** (the build lane gains a broader write-path, or the fs-integrity mechanism is not built), Channel A lapses back to Channel D (human relay) — the same revisit trigger ADR-0034 names, now also guarding the corrective path.
