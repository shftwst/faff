# ADR 0046 — When faff decides an architecture

- **Status:** Proposed
- **Date:** 2026-07-05
- **Issue:** FAFF-346

## Context

The architecture pipeline's propose box shipped as a contract + swappable slot + default occupant, and the gateway advertises it — but nothing invoked it. A user configuring the slot got a silent no-op, and the holdout env step consumed "the architecture proposal" that nothing had ever produced. The proposer/critic boundary is already settled (ADR-0030: the proposer emits an envelope into a spec; the critic reads that spec downstream), but it fixes only the *carrier*, not the *timing* — **when** faff decides an architecture at all: at what point in the pipeline the proposer fires, on what work, and with what bias. Left unrecorded, every future call-site (a planning-loop invocation, the greenfield end-to-end exercise) would re-litigate it.

## Decision

**faff decides an architecture at prep time, only on new-runnable-surface work, under a precision-biased trigger — and the spec is the sole carrier to every downstream consumer.**

- **Prep-time, both spec-producing flows.** The proposal is generated by faff-prep's conditional architecture step — a shared subroutine invoked from the interactive flow (between explore and spec dispatch) and the autonomous fresh-spec flow (before spec production). Prep is where the spec is produced, and the settled boundary (ADR-0030, which this implements and does not amend) requires the proposal to land *in* the spec so the critic critiques it before anything is built.
- **New-runnable-surface only.** The step fires only when the issue + explore findings show a new runnable system or a material deployment-shape change with *no established architecture to inherit* — and no sibling spec in the same project already carries a proposal for the same system.
- **Precision-biased: uncertain → skip.** This is deliberately the opposite bias from the recall-biased spec-review lens selection. A spurious proposal injects unfounded architecture prose into a spec; a missed one costs nothing beyond the status quo and is caught fail-closed by the downstream holdout gates.
- **The spec is the carrier.** The validated proposal block lands verbatim in the attached spec; the spec-review architectural lens (the critic) and the holdout env step (the provisioner) read it from the spec — never handed out-of-band, never regenerated downstream.

## Consequences

- **Absent-proposal posture is explicit and backwards-compatible.** A spec with no proposal block reaches the env step as: derive services from the infra profile, record an explicit "no architecture proposal" note in the handle, treat the recommendation gate as `build` (no buy/hybrid signal exists to honour). This is today's de-facto behaviour made explicit — no existing run regresses.
- **Prep-side failure degrades loud, never parks.** The proposal is an enrichment of spec production, not a gate; a failed dispatch or contract-fold proceeds to spec production with no proposal and a loud surface. The gates that depend on its consequences (env-handle, holdout-verdict) already fail closed.
- **The trigger is the recalibration seam.** If the precision bias proves too tight (the step never fires on real greenfield work), the fix is the trigger prose — the dispatch/fold/consumption path is trigger-independent. The trigger rule is written call-site-agnostically, so a future planning-loop invocation reuses the same dispatch + fold.
- **Rejected: holdout-time generation.** A proposal produced after the build is one the critic never critiques and the build never followed — provenance theatre that collapses the proposer/critic boundary. The absent posture exists precisely so this is never needed.
- **Rejected: the jot/plot call-site.** Conceptually natural for greenfield formation, but a double-future dependency (interactive skills plus a planning loop that does not yet exist); the trigger's call-site-agnostic form keeps that door open.
- **Rejected: a recall-biased trigger.** Firing on every architecture-bearing classification would dispatch a proposer on most tickets and inject unfounded proposals.
- **Rejected: future-fencing the slot instead of wiring it.** A "future capability" label on machinery whose first exercise is already planned against it existing trades one drift (claimed-but-unwired) for another.
