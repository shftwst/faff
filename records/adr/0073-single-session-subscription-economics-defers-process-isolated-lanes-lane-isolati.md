# ADR 0073 — Single-session subscription economics defers process-isolated lanes; lane isolation is a portability-era decision

- **Status:** Accepted
- **Date:** 2026-07-15

## Context

faff's agent lanes (orchestrator / implementor / evaluator, gateway → Agent Lanes) are **contexts inside one Claude Code session**: claude-code manages every subagent (only explicitly-external adversarial calls go via API), so the whole pipeline bills as one session under the Claude subscription quota. That is a deliberate economic choice, not an accident — it is dramatically cheaper than per-lane API billing, and even `claude -p` under subscription has been publicly questioned by Anthropic (early 2026) as to how long it stays available. Multiplying claude processes per lane — nested containers, sibling cages, or plain extra processes — is exactly the expensive/uncertain thing.

The corrective-artifact integrity mechanism (FAFF-325, ADR-0039, ADR-0061) attests that the **build lane cannot write the forge evidence** (`run-ledger.json`, `corrective/`, `events.jsonl`, per-issue verdict files) — a property whose only mechanically-honest implementation is a read-only mount, which is a **process-tree** property. A lane that is a context, not a process, cannot be given a different filesystem view than the orchestrator sharing its process. Two prior artifacts quietly assumed the expensive thing: the original FAFF-514 ticket ("the build lane should run as / inside the nested build container") and the FAFF-313 multi-cage spike (sibling cages per lane) — both require a second claude process. Separately, the claude-box nested engine (FAFF-380, claude-box `93ed538`) exists to stand up **SUT environments for the holdout evaluator** (the `env` slot's docker-compose stand-ins), not to spawn privilege-differentiated claude instances.

## Decision

1. **Single-session, subscription-billed operation is the governing architecture for now.** All lanes run as in-session subagents of one claude-code process. No faff or claude-box work may assume a per-lane claude process (nested or sibling) until this ADR is revisited.
2. **Process-isolated lanes are deferred to the portability/config-DSL era**, when provider/harness-agnostic splitting is tackled deliberately (the natural first candidate is the implementor lane on a cheap API model via the existing `models.build` / engine-lane machinery). Containerising the lanes is expected then — this defers, it does not reject.
3. **The corrective-integrity preflight leg therefore stays an honest REFUSE today.** No launcher (human or cage) can truthfully declare `FAFF_INTEGRITY_BOUNDARY`, because the property it attests describes a process boundary that deliberately does not exist. The fail-closed refusal is the system telling the truth; the implementor-forges-evidence threat remains model-compliance-bounded, as the gateway's mechanical-vs-compliance table already admits for other cells.
4. **The claude-box nested engine remains SUT-env plumbing only.** Lane isolation, when it comes, is a launcher-level concern (per-lane mounts set by whatever launches the lane processes), not an in-cage engine spawn-seam concern.
5. **Two harness-layer intermediate rungs are sanctioned**, both honestly weaker than a kernel mount, and neither may **ever** feed the `FAFF_INTEGRITY_BOUNDARY` channel (that would be precisely the lying attestation ADR-0061 forbids):
   - **Digest-bracketing (preferred — detective, custody-based).** The trusted dispatcher hashes the evidence set immediately before dispatching an untrusted build subagent, holds the digest **in its own conversation context** (subagent context isolation is the one mechanical boundary that exists in-session — the subagent structurally cannot read or write the dispatcher's context), re-hashes immediately on return via an absolute root-owned binary (`/usr/bin/sha256sum` — image fs, unwritable by the session uid), and refuses to consume the evidence on mismatch. This survives where ADR-0039 rejected signatures: signatures need a key on disk the same-uid build lane can read; here the secret is *custody of the digest*, which lives in a context, not the filesystem. Honest residuals: the same-uid tool-poisoning arms race (mitigated, not eliminated, by root-owned-binary verification), digest custody across compaction (verify immediately on return), append-only files checked as prefix-preserving, and parallel-executor bookkeeping for the orchestrator's own in-flight writes. Surfaces as its own trust class (e.g. an `integrityGate` basis distinct from mount-asserted).
   - **A PreToolUse write-fence** (denying tool writes to the integrity paths during build-subagent turns, like `merge-fence`/`background-fence`) — weaker than digest-bracketing (it sees tool inputs, not ground-truth outcomes) and only worth building as a complement.

## Consequences

- FAFF-514 (the `faff integrity-boundary` emitter) is unaffected — it owns the declaration's *content* and is indifferent to when/how the boundary becomes real; it serves hand-operators and the future launcher alike.
- FAFF-517 (cage-side read-only mount + attestation) is re-scoped: blocked on the portability-era lane-split decision, not merely on FAFF-516; its mechanism is launcher-shaped, not engine-shaped. The full pre-split design (grounded cage changes, mount grains, `--init` channel options, lane-cut analysis) is preserved on that ticket as the historical reference to resume from.
- FAFF-516 (the `--init` attestation-channel decision) drops from High priority: still a real mechanical conflict that must be decided **before** the boundary ever becomes real (and the `docs/guide/unattended.md` hand-attestation caveat stands), but the flow it unblocks is itself premised on the deferred boundary — it no longer blocks anyone today.
- `docs/guide/unattended.md`'s trust framing should present the corrective-integrity leg as *deferred pending process-isolated lanes* (an economic architecture decision), not as an operator gesture awaiting automation.
- The digest-bracketing rung is buildable now, in-session, under subscription — it is the sanctioned interim integrity mechanism between FAFF-514's emitter (buildable today) and FAFF-517's real mount (deferred), and is captured as its own ticket.
- Any future ticket proposing per-lane processes, per-lane cages, or in-cage claude spawning must cite and revisit this ADR first.
