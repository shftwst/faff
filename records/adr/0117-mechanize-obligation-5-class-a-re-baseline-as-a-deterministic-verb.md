# ADR 0117 — Mechanize obligation-5 Class-A re-baseline as a deterministic verb

- **Status:** Accepted
- **Provenance:** loop
- **Date:** 2026-08-20
- **Issue:** FAFF-853

## Context

ADR-0078 fixed the shape of obligation 5's Class-A re-baseline sequence — verify the old baseline, perform the write, post-write check, snapshot the candidate, check the candidate's intended content — but left it as **prose the executor hand-chains**, five separate steps a sequential agent orders itself on every trusted write (`corrective author` adding a `corrective/<seq>-<issue>.json`). FAFF-843's spec-review caught a timing hole in exactly that hand-chaining: nothing stopped a tamper from landing between two of the five reads and being absorbed into the new baseline. ADR-0078 has stayed `Proposed` since 2026-07-17 for this reason — the sequence it specifies is correct, but correctness resting on an executor manually getting five ordered steps right, every time, is the same model-compliance bar the rest of obligation 5's bracket runs on, and it is the most error-prone part of that discipline.

Separately, ADR-0114 admitted the digest-custody basis into the corrective consumer's authority fold and, in its Consequences, named a residual: `cmdCorrectiveCheck`'s `--manifest` branch validated only that `members` is a non-null object, so an empty-members manifest (`{version:"d1",grain:"run",members:{}}`) passes that shape check and reaches branch 3 (`custody-trusted`) having verified nothing. That is a **negligent** hollow — a manifest nobody adversarial had to forge, just one that was never populated — distinct from an **adversarial** hollow (a full-roster snapshot taken at consumption instead of pre-dispatch), which is inherent and unclosable: the manifest carries no temporal witness, so the two are bit-for-bit indistinguishable on disk.

Both gaps sit one layer below the authority fold ADR-0114 owns and are addressed by mechanizing the sequence ADR-0078 specifies, not by changing what either ADR already decided.

## Decision

Ship `faff integrity-digest rebaseline` (FAFF-853): a new action on the existing `integrity-digest` CLI that runs obligation 5's Class-A post-write sequence — verify-old, post-write check, snapshot-candidate, intended-content check — as **one atomic op**, deterministic and unit-testable, replacing the hand-chained prose. Given the held baseline `M` (stdin, never a writable path — the same rule `verify` already enforces), the just-written path, and the writer's reported sha256 of the bytes it wrote, the verb runs a single `diffAgainstManifest` of `M` against disk *after* the write: one diff simultaneously proves `M` still holds everywhere except the touched member (subsuming the old pre-write verify) and names exactly what moved (the post-write check's "exactly the touched member" requirement). It then snapshots the candidate `M′` and checks the touched member's recorded hash against the reported one. The verb mirrors `verifyAndRecord`'s never-silently-clean posture (FAFF-784): `M′` reaches stdout **only** on a fully clean fold (exit 0); a tamper on any other member, an unobserved claimed write, or an intended-content mismatch is exit 1 with no manifest; a hollow/wrong-grain baseline, a malformed `--reported-sha256`, or an unresolvable hasher is exit 2 with no manifest. The verb mechanizes the **inputs** to verify — it does not touch `foldCorrectiveAuthority`'s five-branch table (ADR-0114); a re-baselined `M′` is consumed by an ordinary `verify` exactly as any hand-built baseline is. `MANIFEST_VERSION` stays `"d1"`: the members shape gains no field, so bumping it would be a false compatibility signal. v1 folds exactly one Class-A touched member per invocation; Class-B direct-edit re-baseline (no CLI-reported hash exists for the orchestrator's own session edit) and multi-member atomic writes stay hand-chained, named extension points, not attempted here.

Alongside the verb, close the ADR-0114 negligent-hollow residual: `cmdCorrectiveCheck`'s `--manifest` branch now refuses (exit 2) a manifest whose `members` lacks either `corrective` or `run-ledger.json` — the two members `correctiveIntegrityDirs` always returns, grain-invariant, so no legitimate baseline omits them and the guard is default-on. This is a **narrower, consumer-side companion check**, not a change to the fold's branch table: it runs before the fold, on the manifest's shape, exactly where the existing (now-tightened) shape check already ran. It closes the *negligent* hollow only — the *adversarial* hollow stays exactly as ADR-0114 and this ticket's own spec describe it: inherent, backstopped by the obligation-5 on-return verify plus container isolation, never by an on-disk check.

**ADR-0078 is promoted from `Proposed` to `Accepted`.** Its decision — one continuous run-grain custody chain, re-baselined around each trusted write via the fixed step order, Class A/B split by whether a CLI-reported hash exists — is retained unchanged; this ADR mechanizes the Class-A arm of that sequence, closing the FAFF-843 spec-review's timing-hole finding, and mechanization is what moves it from "specified" to "implemented and trustworthy enough to accept." Promotion, not supersession: nothing ADR-0078 decided is reversed. ADR-0078's own Status line is edited in the same commit as this ADR, with an amendment note citing this ADR and FAFF-853.

**ADR-0114 is extended, not amended.** Its five-branch fold table (`foldCorrectiveAuthority`) is untouched — this ADR ships the negligent-hollow companion check as a precondition on the `--manifest` branch a full layer below the fold, exactly the "detection ahead of consumption" pattern obligation 5 already uses elsewhere. ADR-0114's own residuals list already named the empty-manifest gap; this ADR is the follow-through, not a reopening of the fold decision.

## Consequences

- The obligation-5 Class-A re-baseline is a single deterministic CLI call from here forward — `SKILL.md`'s obligation-5 prose (line ~1165) now names the verb directly, and every occupant's own placement prose refers back to it rather than restating the five-step sequence. The FAFF-843 spec-review's timing-hole finding is closed by construction: a caller cannot skip or misorder a step it no longer hand-chains.
- `cmdCorrectiveCheck` no longer grants `custody-trusted` off a manifest that verified nothing. No real caller is affected — every legitimate baseline already carries both core members — so this is a pure tightening with no compatibility cost.
- The honest limit stands, unclosed, by design: no mechanical, adversarial-proof hollow-verify guard exists or is claimed. A well-formed full-roster manifest snapshotted at consumption instead of pre-dispatch remains bit-for-bit indistinguishable from an honest one. The backstop is unchanged — the obligation-5 on-return verify (which parks a real forgery before consumption) plus container isolation — and this ADR closes only the false-tamper and negligent-hollow directions, exactly as FAFF-853's spec scoped it.
- Two named extension points are left for a future ticket, not built here: a `rebaseline --held-copy <file|->` mode composing Class B from a supplied baseline-verified copy instead of a reported hash, and a repeatable `--written-path`/`--reported-sha256` pair set for a single write touching more than one bracketed member.
- This ADR supersedes nothing. ADR-0078's decision (one chain, the write sequence, the Class A/B split) is retained and merely mechanized. ADR-0114's fold table and its narrowed-authority grant are untouched; the negligent-hollow check this ADR adds is a precondition the fold never sees. Both ADRs stay in force alongside this one.
