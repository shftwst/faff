# FAFF-1195: write Commissaire governor key material with owner-only file permissions

> Spec: faffter-dark-nlspec · 2026-10-07 · interactive · claude-code/unknown · confidence: high. Full spec on Linear FAFF-1195.

This spec is for the build agent and human reviewers of FAFF-1195. It changes how `faff commissaire contract admit` writes the files that hold signing and HMAC key material, so a new run never leaves those secrets readable by other local users.

## Why

`cmdAdmit` in `plugin/skills/faff/bin/lib/commissaire.ts` writes two secret files through one helper, `writeJson`, which calls `fs.mkdirSync(..., { recursive: true })` and `fs.writeFileSync(path, body)` with no mode. Both calls therefore take the process umask. Under the usual umask `022` the files land at `0644` and their directories at `0755`. On this Mac, `.faff/runs/run-20261006-144449-graft-FAFF-1208/commissaire/governor/governor.json` is `-rw-r--r--`, and so is `commissaire/producer/producers/run-20261006-144449-graft-FAFF-1208.json`.

`governor.json` holds `sk` (the Ed25519 signing key, `SK_commissaire`) and `master_secret` (the HMAC master from which every producer key is derived). `producers/<id>.json` holds `key_hex`, the derived producer HMAC key. Any local user who can read the run directory can read both, sign grants and forge producer records. On a single-user laptop the exposure is small; on a shared host or a CI box with several accounts it defeats the signature.

This change makes `admit` create the two secret files with mode `0600` from the moment they exist, and create their directories `0700`. Existing run directories are not touched, and every reader keeps working on them.

**Design principles**

- **Never wider, not "fixed later".** A secret file must never exist on disk with a mode wider than `0600`, not even for the instant between create and `chmod`. Any design that writes first and tightens afterwards is rejected.
- **Evidence is not rewritten.** Run directories already on disk are evidence for `audit verify` and the merge floor. Nothing in this change alters a file or directory it did not create in the same call.
- **Readers stay mode-blind.** No reader starts checking or enforcing file modes. A pre-fix run with `0644` files must verify exactly as it does today.

## Out of scope

- **Tightening existing key files or directories.** Why excluded: rewriting modes in existing run directories mutates evidence, and the ticket's open question defaults to "no". Extension point: a separate one-off migration command beside `cmdAdmit` in `commissaire.ts`, if a human later wants it.
- **Warning when an operator-supplied `--governor-dir` or `--producer-dir` already exists with group or world access.** Why excluded: the directory belongs to the operator and the ticket asks only for directories `admit` creates. Extension point: a preflight check in `cmdAdmit` before the mint.
- **Changing the mode of `commissaire/producer/pk.json`.** Why excluded: it holds only the public key and is deliberately copied into committed anchors. It stays at the umask default (it does sit inside the now-`0700` `producer/` directory). Extension point: none needed.
- **Moving the signing key out of the run directory.** Why excluded: that is the out-of-process governor work, FAFF-1177 and FAFF-1216. Extension point: `readGovernorRecord` and the new secret-file writer in `commissaire.ts`.
- **Partial-write cleanup when the producer file write fails after `governor.json` succeeded.** Why excluded: today's behaviour, unrelated to modes. Extension point: `cmdAdmit`.
- **Updating `docs/rfc/rfc-superdomestique-runtime/v5/STATE-AUTHORITY-MAP-v5.md`.** Why excluded: the map is a snapshot pinned to commit `475c0362`; its "writeJson sets no file mode" rows are accurate for that commit. Extension point: the map's next in-place revision.
- **Windows.** Why excluded: the Commissaire CLIs refuse to run off POSIX (`cliPosixGuard`), so POSIX modes are the only case.

## What

**Vocabulary**

| Term | Definition |
|---|---|
| Secret file | A file holding signing or HMAC key material: `<governor dir>/governor.json` and `<producer dir>/producers/<producer-id>.json` |
| Key directory | A directory `admit` uses to hold secret files: the governor directory, the producer directory, and `<producer dir>/producers/` |
| Governor directory | `--governor-dir` when given, else `<run-dir>/commissaire/governor` (`governorDirOf`) |
| Producer directory | `--producer-dir` when given, else `<run-dir>/commissaire/producer` (`producerDirOf`) |
| Owner-only | File mode `0600` (owner read and write); directory mode `0700` (owner read, write, search) |

**Interfaces (internal to `commissaire.ts`)**

```
FUNCTION ensureOwnerOnlyDir(dir: Path) -> void
  # Creates dir with mode 0700 if it does not exist. Creates missing ancestors with the
  # default mode. Never changes the mode of a directory that already exists.

FUNCTION writeOwnerOnlyJson(target: Path, value: JSON) -> void
  # Writes JSON.stringify(value, null, 2) + "\n" to target so that target is mode 0600
  # from the instant it exists. Replaces an existing target atomically. Throws on failure,
  # leaving neither a partial target nor a temporary file behind.
```

`writeJson` stays as it is and keeps writing `pk.json`. Both new functions are exported from the module's existing export list so tests can reach them; no other module calls them.

**Decision: how the secret file gets its mode**

| Option | Never wider? | Replaces existing file? |
|---|---|---|
| `writeFileSync(p, body, { mode: 0o600 })` | Yes on create; no on overwrite (mode applies only when the file is created, so a `--force` rotation over a `0644` file stays `0644`) | In place, not atomic |
| `writeFileSync` then `chmodSync(p, 0o600)` | No (wide for an instant) | In place |
| Open a sibling temp file exclusively (`wx`) with mode `0600`, write, close, rename onto the target | Yes, in every case (the target name only ever points at an inode created `0600`) | Atomic |

**Chosen:** the exclusive temp file with mode `0600`, then rename onto the target. It is the only option that holds the never-wider principle on a `--force` rotation, and it follows the repository's existing temp-then-rename idiom (`atomicWriteSingleValueFile` in `heartbeat.js`).

**Decision: which directories become `0700`**

**Chosen:** only the key directories `admit` itself creates: the governor directory, the producer directory and `<producer dir>/producers/`. Missing ancestors such as `<run-dir>/commissaire/` keep the default mode, because `commissaire/` also holds non-secret files (for example `governance-required.json`) and `fs.mkdirSync(..., { recursive: true, mode })` would otherwise apply `0700` to every directory it creates. A key directory that already exists keeps its current mode.

**Decision: where the helpers live**

**Chosen:** inside `commissaire.ts`, next to `writeJson`. Key custody is Commissaire's alone, and a new local `require` would change the module's local-require allowlist (the "require-graph" test in `test/commissaire.test.mjs`) and the standalone binary's require closure (the import-independence test in `test/commissaire-standalone.test.mjs`). `node:crypto`, already required inline in `cmdAdmit`, supplies the temp-name randomness.

## How

**Behaviour summary.** `cmdAdmit` keeps its order of operations and its exit codes. Only the two secret-file writes change: each goes through `writeOwnerOnlyJson` after `ensureOwnerOnlyDir` has prepared its directory.

```
PROCEDURE ensureOwnerOnlyDir(dir):
  1. IF dir exists (any file type): return without changing anything
  2. mkdir parent(dir) recursively with the default mode   # ancestors are not key directories
  3. mkdir dir with mode 0700 (non-recursive)
     IF this fails with EEXIST (a concurrent creator won): return
     ELSE rethrow any other error

PROCEDURE writeOwnerOnlyJson(target, value):
  1. tmp := same directory as target, name ".<basename(target)>.<pid>.<random hex>.tmp"
  2. fd := open(tmp, flags "wx", mode 0o600)               # exclusive create; never reuses a file
  3. TRY:
       write the serialised JSON to fd; close fd
       rename(tmp, target)                                  # atomic replace within one directory
     ON ANY ERROR:
       close fd if still open (ignore errors)
       unlink tmp (ignore errors)
       rethrow the original error

PROCEDURE cmdAdmit secret writes (replacing the two writeJson calls for secrets):
  1. ensureOwnerOnlyDir(governorDir)
  2. writeOwnerOnlyJson(governorDir/governor.json, { sk, pk, pk_fingerprint, master_secret })
  3. ensureOwnerOnlyDir(producerDir)
  4. ensureOwnerOnlyDir(producerDir/producers)
  5. writeOwnerOnlyJson(producerDir/producers/<id>.json, { ...unchanged fields })
  6. writeJson(producerDir/pk.json, { pk, pk_fingerprint })  # unchanged: public key
```

The umask can only remove bits, so `0600 & ~umask` and `0700 & ~umask` are never wider than owner-only. Under any normal umask the result is exactly `0600` and `0700`.

**Edge cases**

- `--force` rotation in a run whose `governor.json` is `0644`: the rename replaces the old inode, so the new `governor.json` is `0600`. The directory keeps its existing mode.
- `--governor-dir` or `--producer-dir` naming a directory that does not exist: it is created `0700`, its missing ancestors with the default mode.
- `--governor-dir` or `--producer-dir` naming an existing directory: its mode is left alone; the secret file inside is still `0600`.
- A failed write or rename: the error propagates exactly as a `writeFileSync` failure does today, and no `.tmp` file remains.
- Readers (`readGovernorRecord`, `readJson` on producer files, `readChokepointKeyRecord`, `audit verify`, `contract status`, `effect authorize`, `verdict conclude`, `merge-gate`, `mintIssueAnchor`) are unchanged and never inspect modes.

**Anti-pattern:** `fs.mkdirSync(dir, { recursive: true, mode: 0o700 })`. Why: Node applies the mode to every directory the call creates, which would silently make `<run-dir>/commissaire/` owner-only too and widen the change beyond key directories.

**Anti-pattern:** `chmodSync` on anything that already existed before the call. Why: it rewrites evidence in existing run directories, which this ticket forbids.

**Selftest.** The existing split-key custody block in `commissaire.ts`'s `--selftest` (the round trip run for both the flat and the object-verb spellings) gains two checks: `governor.json` and `producers/P1.json` are `0600`, and the governor and producer directories are `0700`. Both `faff commissaire --selftest` and `bin/commissaire --selftest` run the same code, so both binaries exercise it.

**Documentation.** `docs/guide/verify-run-evidence.md`, under its on-disk evidence table, gains one sentence: runs admitted after this change write `governor.json` and `producers/<id>.json` with mode `0600` inside `0700` directories, and runs admitted earlier keep whatever modes they were written with.

**TypeScript emit.** After editing `commissaire.ts`, run `npm install && npm run build` in `plugin/skills/faff`, and commit the regenerated `commissaire.js` and `build-manifest.json`. `node_modules/` is never committed.

## Design decision rationale

**How should a secret file receive its mode?** Options: a `mode` option on `writeFileSync` (fails on overwrite), write then `chmod` (briefly wide), exclusive temp file plus rename (never wide, atomic). **Chosen:** exclusive temp file with mode `0600`, then rename, because it is the only option that is never wider on both create and `--force` rotation.

**Which directories become owner-only?** Options: every directory `mkdir -p` creates, only key directories, or key directories plus a `chmod` of existing ones. **Chosen:** only key directories that `admit` creates, because ancestors hold non-secret files and existing directories are evidence.

**Should `pk.json` change mode?** Options: `0600` for consistency, or leave it. **Chosen:** leave it, because it is public, anchored into git by design, and already shielded by the `0700` producer directory.

**Where do the helpers live?** Options: a shared I/O module, or `commissaire.ts`. **Chosen:** `commissaire.ts`, because a new `require` changes the standalone binary's guarded import surface for no gain.

**Should readers enforce modes?** Options: refuse or warn on wide modes, or stay mode-blind. **Chosen:** stay mode-blind, because the ticket requires `audit verify` to keep reading pre-change runs unchanged.

**Should the write `fsync` before rename?** Options: add `fsync`, or match today's durability. **Chosen:** match today's durability (no `fsync`), because durability is outside this ticket and `writeFileSync` never synced either.
