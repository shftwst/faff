# Adversarial-review skill diet

The review occupant loads 74,897 bytes, including explanations of transport,
retry, parser and process-group behaviour already implemented by its helpers.
Reduce runtime prose while retaining the invocation recipe, every exit outcome,
finding obligations and the separate ADR/PRDR challenge interfaces.

## Boundaries

- No runtime implementation, config default, verdict vocabulary or authority
  change. The existing helpers retain transport, chain assembly, deadlines,
  attribution, output parsing, fixture caps and auto-refutation.
- Keep the independent review lens, Phase-1 short circuit, autonomous critical
  escalation, L3 advisory outage annotations and L4 fail-closed outcomes.
- Pass the run directory on every autonomous call. The helper derives mandatory
  status from the ledger. Preserve checkpoint timing and trusted resume hints.
- Preserve the existing required reads: Phase 1 delegates to the noon reviewer;
  the remote system prompt embeds the shared fixture guidance. Add no mandatory
  reference. Operator configuration documentation is not a runtime dependency.
- Preserve the separate ADR and PRDR challenge contracts, their backend consumer
  choices and their missing-answer rejection. PRDR uses proposal-shaped input.
- Keep finding provenance, carry handles, settled evidence, terminal comment
  granularity and independent rebuttal handling.

## Verification

Freeze source, scenarios and oracle before candidate authoring. Measure five
fresh Claude samples per arm on the final 37-case fixture. Record no-policy
control and all preliminary fixtures, including a corrected invalid verdict
name and a clarified answer shape. Fail any candidate with a new unsafe signal,
missing obligation or changed decision. These are correlated decision probes,
not end-to-end reviews or a statistical non-inferiority result.

Run existing helper tests covering chain assembly, output/exit semantics,
context windows, fixture resolution, progress checkpoints, process lifecycle
and trimming. Run adapter/prose checks, account for each deleted block and lower
the size baseline only after verification. Record before/after bytes and
estimated tokens in the cumulative ledger.
