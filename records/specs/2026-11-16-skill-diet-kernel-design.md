# Shared configuration kernel diet

Compress only Configuration, Slots and Model/effort selection in the shared
kernel. The content before Configuration and from Agent Lanes onwards remains
byte-identical to baseline a8509086ad28fa0e55cf3d1d818f2055294e663b. Preserve the
raw-write exception and tracker-discovery paragraphs verbatim. Add no mandatory
reads, helpers, dependencies or changed defaults.

## Scope and acceptance

- Remove repeated rationale and illustrative configuration blocks; keep every
  operative path, precedence rule, failure mode, slot default and trust boundary.
- Use the unchanged real configuration and dispatch CLI in private Git fixtures.
  Nine executed cases cover layered slot selection, defaults, surgical scalar
  writes, malformed base/overlay, invalid legacy names, build precedence, missing
  tier and whole-tree rejection of an unused invalid leaf.
- Treat downstream skills as prevalidated controlled stubs. This checks dispatch
  selection and arguments, not the complete producer workflow or adapter lint.
- Report 24 separate policy decisions separately from executed cases. Five
  unchanged samples started before candidate authoring; five candidate samples
  must pass every intended case and native tool audit. Preserve all failures.
- Keep earlier V1 fixture failures separate. Its interface correction is recorded
  in workflow-fixtures/KERNEL-CONFIG-V2.md. No failing sample is rerolled.
- Run the existing configuration/write/dispatch tests and adapter lint. Rule
  inventory is a coverage check, not a claim that unit tests establish model
  equivalence. Worker captures supply the behavioural evidence.
- Count source bytes and ceil(UTF-16 characters/4) per file. Recorded payloads are
  separate estimates, not provider billing. Do not qualify savings until both
  arms and native logs have been assessed.

Evidence: verification/experiments/2026-11-16-skill-diet/. Candidate source is
candidates/kernel-v1.md. Measurement plans and their pinned runtime commit bind
