# Thematic read-only skill diet

Shorten the graph-derived methodology's read-only rules without changing its
tracker mutation, eligibility, PRDR-authoring or YAGNI sections. Baseline is
`a8509086ad28fa0e55cf3d1d818f2055294e663b`. No new helper or mandatory read is added.

## Scope and acceptance

- Sixteen named requests separate twelve decisions, three persisted ticket
  proposals and one termination-policy output. Consume that policy through nine
  real `faff run-done` cases and nine contract validations per sample.
- Both arms receive the same complete original kernel and methodology gateway,
  plus global and repository guidance. Start five unchanged samples before
  authoring; measure five candidate samples, retain all failures and audit native
  tools. No tracker fetching, writing or full caller workflow is claimed.
- Preserve backlog-diagnostics, standup-digest, build-queue, crank-up-set,
  prdr-author and yagni-judge byte for byte. Preserve the appetite table and
  topology-write authority. Bind those hashes in the source review.
- Read every persisted ticket proposal for source facts, open questions, status,
  homes and dependencies. Require intended candidate cases and native audit to
  pass before counting the cut. Small correlated samples do not prove statistical
  equivalence.
- Count source bytes and ceil(UTF-16 characters/4) per file separately from the
  recorded payload proxy and provider billing. Source inventory is a coverage
  check; unit tests exercise the grader/consumer, not every prose rule.

Evidence lives in `verification/experiments/2026-11-16-skill-diet/`; the frozen
acceptance is `workflow-fixtures/THEMATIC-READONLY-V1.md`, and the candidate is
`candidates/thematic-v1.md`. The candidate qualifies 60/60 decisions, 15/15 ticket proposals and five termination-policy outputs per arm. Those policies pass 45/45 real CLI scenario consumptions and 45/45 contract validations per arm. All ten native audits pass; all 30 ticket artifacts were read for source fidelity. See thematic-v1-qualification.json.
