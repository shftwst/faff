## Q1 — scope call: per-lane cages vs evaluator-only

**Hypothesis:** the ladder, not a binary — v1 stays one cage + context isolation; next rungs in value order FAFF-325 (fs-integrity) then FAFF-276 (evaluator cage); full per-lane cages unscheduled behind named triggers.

- **Attempt 1 (invariant-contradiction vs ADR-0010) → SURVIVES, with a formal note.** Per-lane cages do not contradict ADR-0010 — they are its *named escalation path*: consequence :47 scopes within-container lane isolation out to FAFF-32, and revisit trigger :48(a) says reopen "if faff needs finer-than-container isolation between lanes that the container can't give". But the full multi-cage rung is not "within-container" isolation — it replaces the singular cage topology ADR-0010 describes ("running Claude Code inside **a** container") with N cages. So the ADR must state that the top rung, when its trigger fires, **formally reopens ADR-0010 via its own :48(a) trigger** — an extension by the ADR's own mechanism, not a quiet contradiction.
- **Attempt 2 (threat case — does any live threat need a build-lane cage now?) → SURVIVES.** The two live threats each have a cheaper named rung: (a) evaluator-reads-code breaks the trust anchor → FAFF-276's cage; (b) build-lane forges orchestrator artifacts (ADR-0039's shared uid+fs finding, extended to detection by :40) → FAFF-325's read-only mount / signatures, which needs **no new cage** — a mount/verification mechanism is strictly cheaper than a container. The one threat only a full per-lane split fixes is secret separation: lanes share one process env, and the harness offers no per-subagent env scrubbing, so FAFF-32's lane→secret matrix is *specifiable but not enforceable* below the per-lane-cage rung. That is exactly the top rung's trigger, not a reason to build it now.
- **Attempt 3 (YAGNI on the evaluator rung — is attestation enough?) → AMENDS: the FAFF-276 trigger has already FIRED for L4.** FAFF-276's own ticket says it "MUST close before the holdout verdict ever gates a lights-out merge (in v1a the verdict gates nothing automatically)". That was true when filed (2026-06-28) — but FAFF-309 has since shipped: under the L4 lights-out signal the per-run holdout phase pipes the verdict through `faff contract holdout-verdict` → `faff prdr coverage` → `faff run-done` with `prd_satisfied === false ⇒ escalate` (beep-boop §10b), and the per-issue graft merge-gate reuses the same `holdout_step`. The verdict is now **load-bearing at L4**, so the code-blindness it rests on is a live single point of trust held only by convention + attestation. The ladder ordering survives, but FAFF-276's rung is re-classified from "later, on trigger" to **triggered-now for L4 use** (L1–L3 unaffected — no holdout phase runs there).

**Close: AMENDED-SURVIVES.** Ladder confirmed with per-rung owners + triggers; v1 stopping point (one cage + context isolation) confirmed — the ticket's promotion-intent line holds; FAFF-276's trigger recorded as fired for L4; the top rung formally reopens ADR-0010 when its trigger fires.

## Q2 — the outer orchestration layer + the intent seam

**Hypothesis:** outer layer = the existing HOST altitude (human today; CI / factory-compute later); seam = intent-out / assert-in (faff emits a declarative lane-boundary artifact, the outer layer provisions, each lane asserts + refuses at entry).

- **Attempt 1 (invariant-contradiction — is emitting intent a launch path?) → AMENDS: the cage/workload distinction must be drawn.** If an outer daemon watches for intent artifacts and launches cages, faff's write is causally a launch. Resolution comes from a distinction the current prose leaves implicit: faff **already launches containers** — the env slot's `docker compose up` (the architecture doc: "the only containers faff launches are the SUT env"). So assert-not-launch cannot mean "faff never launches any container"; it means **faff never launches or widens a *cage* — a permission envelope an agent lane runs in — and never self-grants**. SUT containers are *workload*; cages are *authority*. Under that sharpened wording, emitting a lane-boundary intent artifact is configuration for an outer layer whose provisioning authority was human-granted at setup (exactly as CI acts on a push under pre-granted authority) — no violation. The ADR must state the cage-vs-workload distinction explicitly; it is load-bearing and currently nowhere recorded.
- **Attempt 2 (consumer-breaks — cross-cage dispatch) → AMENDS: the seam needs a handoff pattern, not just an assertion.** Walking the first real consumer (an evaluator cage) breaks the naive seam: today the orchestrator spawns the evaluator as a fresh process *inside the same cage*; with a separate cage, dispatch must cross a container boundary. Candidate transports: (a) a pre-launched evaluator-cage service on a local socket — new live IPC surface; (b) shared-volume file handoff — **forgeable**, inherits exactly ADR-0039's finding, so it demands the FAFF-325 integrity mechanism; (c) phase-boundary artifact handoff sequenced by the outer layer — the orchestrator emits an evaluation-request artifact, the outer layer runs the evaluator cage, the orchestrator consumes the verdict at its next dispatch boundary, validating it through the existing `holdout-verdict` contract (`code_blind` + shape) plus integrity. Option (c) composes with the shipped stop-and-redispatch philosophy (ADR-0039's dispatch-boundary consumption) and adds no live cross-lane channel — it is the seam family the ADR should name, with the transport left to the outer layer and the shared-volume variant explicitly integrity-gated.
- **Attempt 3 (YAGNI — settle the owner now?) → NARROWS.** Who owns the outer layer (human script, CI, factory-compute, a claude-box sibling) is undecidable before a consumer exists, and forcing it would be guessing. The durable part is the seam: the intent artifact's existence + the per-lane assert-and-refuse + the phase-boundary handoff pattern + the integrity requirement. The concrete manifest schema and transport are FAFF-276's build decisions. **Owner recorded as an explicit unresolved boundary: "first consumer decides".**

**Close: AMENDED-NARROWED-SURVIVES.** Seam settled (intent-out / assert-in + phase-boundary artifact handoff, integrity-gated, validated by existing contracts); cage-vs-workload wording added to the invariant; outer-layer owner deliberately left to the first consumer.

## Q3 — the docker-inside-the-cage precondition

**Hypothesis:** an L4 launch precondition; mounted host socket rejected for lane envelopes; dind (or rootless engine) accepted at complexity cost; documented + asserted, never provisioned.

- **Attempt 1 (threat case — the socket) → STRENGTHENS to a contract-level failure.** A mounted host docker socket inside the cage is root-equivalent host control: any lane can `docker run -v /:/host --privileged` and walk the host fs. That does not merely violate a lane envelope — it makes the cage **not host-isolated at all**, so ADR-0010's contract ("host-isolated container + in-container allow-all") is unmet and `container-check`'s contained verdict asserts a containment that is a lie. The criterion is therefore not socket-vs-dind by name but a **boundedness test**: *the engine's authority must be bounded by the cage*. Host socket fails by definition. Plain `--privileged` dind partially fails (a privileged cage weakens host isolation); rootless nested engines (rootless dind, podman-in-podman, sysbox-class runtimes) pass best. Because the cage image is external (claude-box), faff's posture is assert + document: the precondition is stated as a hard requirement in the L4 launch preconditions, and a detection probe (e.g. `/var/run/docker.sock` present ⇒ warn/refuse on the lights-out path) is a **costed follow-up assertion**, not built here.
- **Attempt 2 (repo-contradiction — what does current guidance say?) → DOC-DELTA NOTED.** The current picture blesses both postures: the SVG names "(precondition: a mounted socket / docker-in-docker)" and the external-verification brief offers "host daemon, or docker-in-docker inside the run container". Under the boundedness test that guidance is wrong for L4 (fine for interactive/dev). The ADR supersedes it; the one-line SVG/doc correction rides with FAFF-276's build or the probe follow-up rather than widening this docs-only PR.

**Close: AMENDED-SURVIVES.** The precondition is a hard requirement stated by criterion (engine authority bounded by the cage) rather than by product name; host socket fails it, privileged dind is a named risk, rootless engines recommended; detection probe = costed follow-up; existing doc guidance flagged for correction.

## Q4 — vocabulary + what each rung makes enforceable

**Hypothesis:** each rung is a candidate value of a role's declared `isolation` field (FAFF-73's ceiling); FAFF-32's matrix becomes enforceable only at the per-lane-cage rung.

- **Attempt 1 (repo-contradiction vs FAFF-69/73) → SURVIVES.** FAFF-69's `isolation` values today (`object_store: own-worktree|separate`, `deny_read: […]`) express *context* isolation. Adding a `container: shared | own` axis expresses the ladder exactly: rung 0 = every lane `container: shared`; rung 2 = evaluator `container: own` with an `accesses` envelope excluding `repo` (the FAFF-73 loader-rejection example made physical); rung 3 = all lanes `container: own`, each with its own env, which is the first point FAFF-32's lane→secret matrix is *enforceable* rather than merely specifiable. No contradiction with the floor/ceiling validation model; the ceiling rule ("an override never weakens isolation") extends naturally to the container axis.
- **Attempt 2 (YAGNI — naming field semantics for a deferred DSL) → SURVIVES.** This is the ADR-0038 clause-4 / ADR-0040 move: give the deferred field settled meaning from a proven decision without building the loader. FAFF-73 stays blocked by FAFF-72; nothing here unblocks or builds it — it inherits decided semantics.
- **Enforceability map (recorded for the ADR):** rung 1 (FAFF-325) makes orchestrator artifacts trustworthy against the build lane (detection + corrective inputs — ADR-0039 :25/:40); rung 2 (FAFF-276) makes the holdout verdict's `code_blind` a physical fact, not an attestation — required now that the verdict gates at L4; rung 3 makes the FAFF-32 matrix and per-lane credentials physically enforceable and strengthens ADR-0034's isolation co-binding.

**Close: SURVIVES.** Vocabulary settled as declared-field semantics; enforceability named per rung.
