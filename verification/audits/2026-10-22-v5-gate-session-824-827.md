### Bullet 4: how the code behaves at `64632b5e`

- One file, two schemas. `effects.js:700` `appendEffectEntries` writes `schema:2`. `commissaire.js:200` `appendProducerRecords` writes `schema:3`. Both append to `declared-effects.jsonl` under one lock (`events.js:546`), and `commissaire.js:108-112` says the shared chain is deliberate.
- `schema:2` is suppressed only for covered merges and PR creates (`merge-gate.js:1312`, `:2008`, `:2024`, `:2099`). The `--local` merge path writes no `schema:2` record.
- Everything else in a governed run stays `schema:2`: push, label write, tracker write, file write.
- `computeEscapes` (`effects.js:229`) lets a `schema:3` declare cover a `schema:2` observe. Tests: `test/commissaire-unit-id.test.mjs:265`, `test/merge-gate-commissaire-verify.test.mjs:555`, `test/pr-create-chokepoint.test.mjs:111`, `test/commissaire.test.mjs:1120`.
- `docs/guide/cli.md:210` says new runs are canonical in `schema:3` and `schema:2` is frozen history. The code does not match.
