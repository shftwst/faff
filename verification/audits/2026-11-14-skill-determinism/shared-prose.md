# Shared skill prose: determinism and parity audit

Audit date: 2026-11-14. Source pin: `f767bdd1c0a78f6259c335742c1567a074f512a0`.

This audit covers `plugin/skills/faff/SKILL.md` and every line of its nine `references/*.md` files: 1,295 physical lines. The inventory below follows headings and significant rule ranges, including rules buried inside long paragraphs. V5 documents were read at the authority, ownership, coordination, transition, evidence and later-status sections cited below. Runtime code, defaults and skills were not edited.

The largest opportunity is to remove repeated interpretation of already-defined mechanics: block extraction, tracker fact normalisation, template selection, comment splicing, dispatch preparation, bounded effect plans, and evidence custody sequencing. Judgement about a spec, a human's intent, an architecture, a finding, or useful prose must remain explicit model work. A short command call is not parity if its caller still reconstructs the old algorithm, silently omits a side effect, or receives the old prompt again in stdout.

## Inbound loading and dependency shape

The kernel is loaded by every entry skill and many standalone occupants. Specific entry skills explicitly refuse to load the 79-line bare gateway. A change to the kernel therefore has much wider prompt impact than a gateway-only deletion.

Exact path references and heading references both need compatibility checks when a section moves. Shrinking a file without changing load fan-out leaves unrelated rules resident in each consumer. Conversely, deleting a shared rule because a main caller already uses code can break standalone occupants.
