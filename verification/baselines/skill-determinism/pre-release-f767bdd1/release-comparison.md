# Release and migration comparison protocol

| Reference | Purpose | State |
|---|---|---|
| Pre-release `f767bdd1` | Preserve the system before outstanding work lands | Captured in this directory |
| Released commit and package | Attribute changes made by the outstanding work; establish the migration starting point | Capture after release |
| Migration candidate | Measure each extraction against the released behaviour under the same policy | Work remains paused |

1. Keep this directory and its seal unchanged. Record the released commit, tag, package version and package digest in a separate baseline directory. Retain both source commits.
2. Run `capture.mjs` against an isolated checkout of the released commit, using the same saved `analysis-tool/skill-audit.original.mjs`. The script takes `SOURCE_ROOT AUDIT_TOOL OUTPUT_DIR OPERATOR_ROOT`. It refuses to overwrite an existing capture. Its historical input is the original workspace's local evidence, separately hashed from the source checkout. The five selected local sessions are historical controls; collecting new release runs is a separate step.
3. Compare the file hashes and complete skill inventory first. Review changed entry load declarations, source defaults, local overrides, installer behaviour, skill descriptions, contract schemas, command interfaces and existing golden fixtures. Document each difference caused by the pending issues. Do not attribute those differences to migration savings or regressions.
4. Repeat the recorded unit-suite command and environment, the supplemental compiler checks, `validate-adapters`, `regions check`, `lint-cli-coverage`, and the saved historical replay and reproduction. Compare skipped cases by identity as well as count. Preserve the original failing output if a check fails; record any environmental rerun separately.
5. Repeat `cli-timing.mjs RELEASE_ROOT OUTPUT_JSON` on the same host after other checks finish. It records three warmups and twenty fresh-process samples per command. Compare raw samples and host load, not just a single elapsed time. These timings cover local CLI operations, not model inference or end-to-end work.
6. Test discovery in fresh installation targets for each supported host. Record exact runtime catalogue bytes where obtainable, package identity, resolution precedence and which bodies are actually read. The installed-directory scan here measures only this machine's filesystem. Preserve operator installations while testing. Keep default selection changes separate from loader and prose changes.
7. Before the first prose removal, capture repeated model runs from the released version on isolated, fixed task inputs. Pin model version, effort, system/tool catalogue, slot configuration, task and repository inputs, budget and cache treatment. Record unique request IDs, input/cache/output tokens, wall time, retries, ordered tool attempts/results and final external state. Use independent, declared expected scenarios and effects. Randomise paired run order and report cold and warm cache arms separately. Include uncertain-write, restart, stale-read, concurrency and dependency scenarios where the extracted operation can encounter them.
8. Compare each migration candidate with that release baseline under identical policy. Report prompt bytes, provider tokens, cost, latency, behaviour and evidence coverage separately. Keep dark-default adoption as a separate treatment because it changes the work performed. Historical counterfactual costs cannot supply a measured candidate saving.

Current evidence limitations remain open: six of nine historical decision kernels have no graded observations; the fourteen `next` mismatches are not established avoidable work; the draft parity comparator accepts some incomplete or unsafe-number evidence; managed-comment prose has unresolved cases. None is waived by the passing unit suite. Resolve the comparator and expected-scenario gaps before using it as a migration acceptance gate.

No release, installed-skill change, default change or migration implementation is part of this capture. Pinned development dependencies were installed only inside the isolated worktree to run the compiler checks.
