# PRDR 0001 — link-shortener v1 — persisted runnable service

- **Status:** Accepted
- **Provenance:** loop
- **Date:** 2026-08-29
- **Container:** link-shortener
- **PRD-goals:** ["A running service that mints a code for an absolute URL and redirects that code to the URL.","Codes survive an api container restart, proving the datastore is real rather than in-memory.","An optional time-to-live is honoured: an expired code stops resolving.","The packaged stack starts healthy and answers a liveness check quickly.","An automated test suite covers every acceptance scenario below and passes."]

## Context

The repository has no URL-shortener service. The PRD asks for a small, production-shaped one
backed by a real persistent datastore, runnable and verifiable end to end. This project is the
whole v1 delivery: mint, resolve, TTL, packaging, and the automated test suite that proves the
acceptance criteria. It serves every declared PRD goal.

## Decision

Deliver a single runnable v1 of the link-shortener as three first-slice epics: a persisted
mint-and-resolve MVP packaged under docker-compose (the thinnest runnable slice), optional TTL
expiry, and structured JSON error responses. The api reads config from the environment, stores
codes in a real datastore behind a schema migration, and is health-checked at /healthz. Language,
runtime, and the specific datastore are resolved at the architecture step (creative licence: broad).

## Scope

Covers: POST /shorten, GET /{code}, GET /healthz, persistence across api restart, optional
ttl_seconds, structured JSON errors, a schema migration, env-driven config, docker-compose
packaging, and an automated test suite covering the PRD acceptance scenarios.

Excludes (PRD non-goals): authentication/authorization, custom aliases, analytics or click
counting, any user interface, and deduplication of identical URLs.

## Definition of done

- POST /shorten with a valid absolute http(s) URL returns 201 and a `code` matching `^[0-9A-Za-z]{7}$`.
- GET /{code} (no redirect follow) for an issued code returns 302 with `Location` byte-equal to the stored URL.
- GET /{code} for a never-issued code returns 404.
- A code created with `ttl_seconds: 1` returns 404 on GET at least 2 seconds later.
- The same URL shortened twice yields two different codes.
- A code created before an api container restart still returns 302 with the original `Location` after the restart.
- With the stack started via `docker compose up`, GET /healthz returns 200 within 60 seconds.
- Error responses are structured JSON.
- A schema migration creates the storage table; configuration is read from the environment.
- The automated test suite covering all scenarios above passes.
