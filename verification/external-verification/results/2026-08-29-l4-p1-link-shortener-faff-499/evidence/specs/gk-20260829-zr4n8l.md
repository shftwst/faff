## What to build

New files (a greenfield service; nothing exists in the repo yet):

- `cmd/api/main.go` — process entrypoint: read env config, open the pgx pool, run the startup
  migration, wire routes, serve. Also supports a `-healthcheck` flag: when set, the process GETs
  http://localhost:$PORT/healthz, exits 0 on 200 else 1, and does not start the server — this is the
  compose healthcheck command (distroless has no curl).
- `internal/store/store.go` — the datastore layer over pgx: `Create(url) (code, error)` storing the
  exact validated submitted url string (no normalisation) with collision retry (NULL expires_at this
  epic), `Resolve(code) (url, found, error)` (reads expires_at, always non-expired this epic — the
  column is reserved for the TTL epic).
- `internal/dsn/dsn.go` — a `Redact(databaseURL string) string` helper returning a log-safe DSN
  (host + database, password stripped) for **both** DSN forms: the URL form
  (`postgres://user:pass@host/db`, including a percent-encoded `%40`/`%3A` password) and the
  keyword/value form (`host=... password=...`). Used everywhere a connection/pool error is logged.
- `internal/code/code.go` — 7-char base62 generation from crypto/rand.
- `internal/httpapi/handlers.go` — the three handlers: `POST /shorten`, `GET /{code}`, `GET /healthz`.
- `migrations/0001_create_links.sql` — `CREATE TABLE links (code text primary key, url text not null,
  created_at timestamptz not null default now(), expires_at timestamptz null)`. The `migrations/`
  directory is embedded into the binary with `go:embed` (an `embed.FS` in `internal/migrate`), so the
  SQL is present at runtime inside the distroless image with no COPY/volume. Applied at api startup by a
  `schema_migrations`-tracked runner (`internal/migrate`): a `schema_migrations(id text primary key,
  applied_at timestamptz)` bookkeeping table records applied ids, and the runner applies each embedded
  `migrations/NNNN_*.sql` not yet recorded, inside one advisory-locked transaction, in id order. This
  makes the TTL epic's migration a plain additive embedded file.
- `Dockerfile` — multi-stage: build stage on golang:1.22, final stage a distroless/static image
  with the compiled binary. Exposes PORT.
- `docker-compose.yml` — `api` (built from Dockerfile, env DATABASE_URL + PORT, depends_on db
  healthy, healthcheck `["CMD", "/api", "-healthcheck"]` — the binary's own probe, since distroless
  has no curl/shell) and `db` (postgres:16-alpine, POSTGRES_* env, named volume `pgdata`, pg_isready
  healthcheck, **no `ports:` mapping** so the datastore is not reachable from the host — the api
  reaches it over the compose network only). The POSTGRES_PASSWORD / DATABASE_URL here are
  compose-local dev defaults, marked as such, never production secrets.
- `go.mod` / `go.sum` — module + pinned pgx.
- Tests: `internal/...` unit tests where pure (code generation shape), and an integration/e2e test
  suite that exercises the acceptance scenarios against a running stack (compose up, hit the api,
  assert; including the api-restart persistence scenario). A `Makefile` or test script target that
  brings the stack up and runs the suite.

## How to build it

- **Chosen:** Go 1.22 stdlib `net/http` with the 1.22 `http.ServeMux` pattern router (`POST /shorten`,
  `GET /healthz`, `GET /{code}`). No third-party web framework — the surface is three routes. Note the
  `GET /{code}` wildcard matches **any** single-segment GET path, so the resolve handler owns code-shape
  validation (next bullet) rather than the database silently absorbing malformed paths.
- **Chosen:** Postgres 16 via `github.com/jackc/pgx/v5` (`pgxpool`). One `links` table.
- **Chosen:** Codes are 7 base62 chars (`[0-9A-Za-z]`) drawn from `crypto/rand`. Insert with the
  code as primary key; on a `23505` unique-violation, regenerate and retry (bounded, e.g. 5 attempts).
  This satisfies the `^[0-9A-Za-z]{7}$` shape and guarantees two shortenings of one URL differ.
- **Chosen:** Input validation on `POST /shorten` is strict and pinned, not a loose prefix test.
  The request body is read through an `http.MaxBytesReader` (e.g. 8 KiB cap) so an unauthenticated
  caller cannot exhaust memory with an unbounded body; a body over the cap → 400 (or 413). Parse the
  body as `{ "url": "<string>", "ttl_seconds"?: <int> }`. Validate the url with Go's
  `net/url` `Parse`: require `Scheme` in {`http`, `https`}, a non-empty `Host`, and **reject any raw
  control byte (0x00-0x1F or 0x7F) anywhere in the string**. A non-conforming url → 400. On success
  return 201 with `{ "code": "<7 chars>" }` and store the validated url. `ttl_seconds` is parsed as an
  optional integer field: a body that is not valid JSON of the shape `{url: string, ttl_seconds?:
  int}` → 400 (so a `ttl_seconds` of the wrong JSON type is rejected by the parse); the integer's
  value is otherwise **ignored** this epic (not range-validated, no effect — honouring it is the TTL
  epic). Store NULL `expires_at` this epic.
- **Chosen:** `GET /{code}` first validates the `{code}` path segment against `^[0-9A-Za-z]{7}$`; a
  segment that fails the shape → 404 **without a database query** (a malformed path and a never-issued
  code both return 404 this epic, but the malformed case is decided at the route/handler, giving the
  TTL and structured-error epics a clean seam to distinguish them later). A well-shaped code is looked
  up. Found (and, this epic, always not-expired) → 302 with `Location` set to the stored URL. Unknown
  well-shaped code → 404.
- **Chosen:** the value stored for a code is the **exact validated submitted url string** — the raw
  bytes the client sent, once they pass validation, with **no normalisation or re-serialisation**. So
  `Location` on resolve is byte-for-byte the string the client submitted to `POST /shorten` (AC 2's
  oracle is "submit URL U, resolve, assert Location == U exactly"). Because validation already rejected
  any control byte, the stored string is header-safe; the resolve handler re-checks control-byte safety
  before writing the header as defence in depth (a stored value failing the check → 500, never a raw
  header write), but on the normal path the raw write is safe precisely because the stored string was
  validated at mint.
- **Chosen:** `GET /healthz` returns 200 once the process is up and the db pool answers a ping;
  a plain `200 OK` body is fine. The healthz body never echoes config or the DSN. The compose
  healthcheck runs the api binary's own `-healthcheck` mode (GET localhost/healthz, exit 0/1) — a
  distroless final image has no curl/wget, so the probe must be the binary itself.
- **Chosen:** Config from env only — `DATABASE_URL` (pgx connection string) and `PORT` (default 8080).
  No config file. Fail fast at startup if `DATABASE_URL` is unset. Startup failures and pgx pool errors
  log only a **redacted** DSN (host + database name, never the `:password@` segment) and never surface
  the raw `DATABASE_URL` in any log line, error body, or healthz response.
- **Chosen:** A `schema_migrations`-tracked migration runner (a small bookkeeping table recording
  applied migration ids) applies `migrations/*.sql` at api startup, before the server binds — chosen
  over a bare `CREATE TABLE IF NOT EXISTS` so the TTL epic's and any future migration is a plain
  additive `migrations/NNNN_*.sql` file, not a mechanism change. The `migrations/` dir is embedded in
  the binary via `go:embed`, so the SQL ships inside the distroless final image (no COPY, no volume).
  The runner takes a
  `pg_advisory_xact_lock` on a fixed key at the start of its transaction, reads the applied ids, applies
  each unrecorded migration in id order, records it, and commits — all inside that one locked
  transaction. A concurrent second starter (a restart racing, or a second replica) blocks on the
  advisory lock, then finds every migration recorded and applies nothing. This removes the
  double-start crash race and makes a re-run after an api restart a clean no-op (relevant to AC 5). Keeps
  the P1 schema-migration requirement satisfied without a separate migration container and makes a fresh
  `docker compose up` self-initialising.
- **Chosen:** docker-compose with a named volume for Postgres data, so restarting only the `api`
  service leaves the datastore intact — the restart-persistence acceptance criterion.
- **Assumes:** the datastore column `expires_at` exists now (nullable) so the TTL epic
  (gk-20260829-u9qzgx) is additive **at the schema layer** — no table rebuild. The TTL epic will still
  extend `store.Create`'s signature and the `POST /shorten` write path to persist a computed expiry;
  that is an expected code change in that epic, not a schema-migration break. This epic stores NULL and
  treats every code as non-expiring.
- **Assumes:** `docker compose` (v2) and a container registry are reachable in the build/run
  environment. If not, the holdout env step narrows to the thinnest provisionable target and defers
  the full runnable proof rather than this spec being at fault.
- **Assumes:** the shortener is an open redirect by design (it 302s to any submitted absolute http(s)
  URL) — inherent to the product and not a PRD non-goal. The http(s)-only + host + control-byte gate is
  the standard MVP floor; host allow-listing / an interstitial is out of scope for v1 (noted advisory,
  not a defect).
- **Punt:** the exact base image for the final stage (distroless static vs alpine) is left to the build
  agent — either satisfies the acceptance criteria; pick the smaller one that builds cleanly in-cage.

## Scenarios

Born-verifiable Given/When/Then scenarios (this epic owns PRD P0 plus P1 migration + env-config).
Each is an automated-test oracle.

```
Given a valid absolute http(s) URL
When the client sends POST /shorten
Then the response status is 201 and the body field `code` matches `^[0-9A-Za-z]{7}$`
```

```
Given a code returned by POST /shorten for a URL U
When the client sends GET /{code} without following redirects
Then the response status is 302 and the `Location` header equals U byte-for-byte (U as submitted, no normalisation)
```

```
Given a well-shaped code that was never issued
When the client sends GET /{code}
Then the response status is 404
```

```
Given a single-segment path that fails `^[0-9A-Za-z]{7}$` (e.g. `abc`, or a 20-char base62 string)
When the client sends GET /{path}
Then the response status is 404
```

```
Given the same URL submitted to POST /shorten twice
When both responses return 201
Then the two `code` values are different
```

```
Given a code created via POST /shorten
When the api container is restarted and the client sends GET /{code}
Then the response status is 302 and the `Location` header equals the original URL
```

```
Given the stack started with `docker compose up`
When GET /healthz is polled
Then it returns status 200 within 60 seconds
```

```
Given a POST /shorten body whose url is non-absolute, non-http(s), empty, or contains a raw control byte, or whose ttl_seconds is the wrong JSON type
When the client sends POST /shorten
Then the response status is 400 (and a valid url still returns 201)
```

```
Given a POST /shorten request body larger than the configured size cap
When the client sends it
Then the response status is 400 or 413 and the process does not exhaust memory
```

## DONE

Externally-observable completion assertions (each checkable code-blind against the running stack via HTTP).

- [ ] `GET /healthz` MUST return status 200 when the stack is running.
- [ ] `POST /shorten` with a valid absolute http(s) URL MUST return status 201 with a body `code` matching `^[0-9A-Za-z]{7}$`.
- [ ] `GET /{code}` for an issued code MUST return status 302 with a `Location` header byte-equal to the submitted URL; for an unknown or malformed code it MUST return status 404.
- [ ] `POST /shorten` MUST return status 400 for a non-absolute, non-http(s), empty, or control-byte URL, and two shortenings of one URL MUST return different codes.
- [ ] A code minted before an api-container restart MUST still return status 302 with the original URL after the restart.

## Build-time verification (not part of the code-blind holdout DoD)

These properties are verified by the build's own gated test suite (Step 8 AC verification, `all_verified: true`) and the adversarial code review, not by the black-box code-blind holdout — they are internal/config/unit concerns the holdout evaluator has no external surface to exercise:

- The `links` table exists in Postgres after startup (the `schema_migrations`-tracked, advisory-locked, `go:embed`-embedded startup migration created it).
- The api binds the port given by `PORT` (a run with `PORT=9090` answers `GET /healthz` there, not on 8080).
- Starting the api without `DATABASE_URL` exits non-zero (fail-fast on missing required config).
- The DSN-redaction helper strips the password for both URL-form (including percent-encoded) and keyword/value DSNs (unit test).
- Two concurrent startup migration runs both succeed and the `links` table exists exactly once (the advisory lock serialises them).

(TTL expiry — PRD AC ttl_seconds:1 → 404 — is out of scope here; it is epic gk-20260829-u9qzgx.
 Structured JSON error bodies are epic gk-20260829-tleugm; this epic may return plain-text errors.)
